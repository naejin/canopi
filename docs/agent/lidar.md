# LiDAR implementation guide

Use this entry point for raster import, overlap review, the shared library, analysis, or LiDAR presentation. The current foundation admits bounded, north-up, aligned single-band numeric rasters and persisted slope analysis. The [raster rework](../design/raster-data-analysis-rework.md) specifies future bounded import, Data/Analysis workbenches and shared Web maps; it does not change the current workflow until implemented. The [foundation record](../design/lidar-library.md) retains storage and scientific invariants. Consult bd before claiming a slice.

## Accepted direction and current assignment

The user selected [ordered COG Data Layers](../design/raster-rework/ordered-cog-design.md): an ordered collection of source COGs, topmost-valid composition shared by display/analysis, whole-layer presentation visibility, and no compulsory merged-source raster for new edits. This is accepted direction, partially implemented on the delivery branch and not independently accepted or integrated here. The [implementation prompt](../design/raster-rework/ordered-cog-agent-prompt.md) is the sole active assignment on `canopi-jv8a.4`; it owns the permitted existing-dock UI changes and compatibility transition. [ADR 0027](../adr/0027-ordered-cog-data-layers.md) supersedes ADR 0026 for new source composition.

The current repair baseline is `783e31e3` on `feature/bounded-raster-generations`, retaining accepted native integration `a5fc7d7b` and C1/C2, and this branch carries the implementation. The [independent review](../design/raster-rework/ordered-cog-review.md) requires eleven repair groups despite reported green gates. The design's repair contract settles completion, migration Undo limits and dependent recomputation; `canopi-kko3` needs caller evidence before acceptance. This planning checkout does not contain the delivery implementation. Preserve the branch's newer source/owner inventories, compatibility-lease guidance and revision-labelled receipts when merging this documentation; the inventory below describes the earlier checkout.


Q is unqualified and frozen. Preserve useful regression tests and [historical evidence](../design/raster-qualification-q.md); do not repair or rerun its retired harness assignments. The [review/debrief](../design/raster-rework/review-and-debrief.md) owns historical outcomes and improvement evidence. GDAL and the pinned native reader remain selected; Rust owns native raster work and TypeScript application orchestration. No new Python raster tooling or wholesale Python removal.

Repair inventory: the public collection read holds one catalogue connection and never re-acquires it; the read surface is a bounded summary plus member pages and history pages with snapshot-bound and upper-bound cursors (`lidar_layer_collection`, `lidar_layer_history`). One composition rule applies everywhere — the highest-priority valid sample wins — so published statistics, review counts and reopened samples are the same composition. Admission validates one common CRS and grid anchor for a first batch, refuses a zero-valid source by name, refuses a partially rejected batch at `prepare_apply`/`apply_import`, and measures the envelope from the current composition's extent rather than the fixed lattice anchor. A pre-transition head is wrapped as itself, and a sparse preserved composition keeps its signed chunk extent. Slope eligibility resolves through the composition's members, superseded jobs settle as the scheduler's stale outcome, and a result is Ready only while the source generation it captured is still the head. Undo records its target and whether it is available (schema v16 `undo_available`, `operation`); restore compares ordered occurrence identities. The four edit commands await their own settlement and return `LidarLayerEditOutcome`.

Implementation inventory: catalogue schema v14 adds `lidar_collection_members` (stable `member_id`, top-first `position`, kind `source` | `previous-composition`, originating job) and the snapshot lineage `previous_generation_id`, on top of the v13 asset/chunk/region indexes, per-layer lattice and pre-migration `VACUUM INTO` copy. `collection.rs` owns the ordered snapshot: load, measure, insert and history. `generation.rs` owns one bounded resolver (`CollectionReader`, `GenerationReader`) over the ordered member list; `lidar_generation_members` and the `GenerationChunkReader` remain the read path of preserved generations and of persisted slope results. **Retained source COGs are the only durable member payload**, prepared inside the owning job directory and promoted into the immutable store only at publication with a journalled, no-replace link whose catalogue references commit in the publication transaction. Review and display keep the occupied-region traversal and the bounded native tile transport with the `canopi-raster://` Desktop protocol adapter and a shared bounded tile cache. A preserved dense composition is replayed through one library-owned compatibility lease (`LidarLibrary::compat_lease`), released when its layer is deleted.

Preserve originals/sidecars, source-specific validity, valid zero/negative values and current Float32 semantics. Existing production limits remain unchanged. Legacy dense/sparse assets stay readable exactly; never reinterpret masked historical replacement as simple source order. **A pre-transition head is exposed as one indivisible bottom member labelled "Previous composition"** and is never split into reorderable historical sources. Source order is library data, so a reorder changes every design that references the layer and never dirties a Design; the dock states this once. A committed numeric edit — import, reorder, remove, Undo or restore — publishes a new snapshot and refreshes dependent analyses on settlement, which is how `canopi-kko3` is closed. The later workbench HTML reference `0e696722` does not block the source-list changes in the existing dock. [Collaboration](../design/raster-rework/collaboration-protocol.md) retains main-agent review and user courier authority.

The library owns originals, masks, numeric results, jobs and caches; a Design owns only references and presentation. Shared workspace navigation never changes raster geography or scientific results. Use the current map/camera lifecycle rather than introducing a second map owner.

For native library changes, run the focused `services::lidar` tests and repository Rust gates. The real IGN lifecycle command and prerequisites are in the build guide; an unavailable fixture is not a pass. Frontend tests include `lidar-actions`, `lidar-layer-collection`, `lidar-library-store`, `lidar-map-presentation`, `design-edit-lidar`, and `lidar-camera-navigation` under `desktop/web/src/__tests__/`. Shared contracts require generated-binding checks; shared workspace changes require the edition gates in [AGENTS.md](../../AGENTS.md#quality-gates).
