# LiDAR implementation guide

Use this entry point for raster import, overlap review, the shared library, analysis, or LiDAR presentation. The current foundation admits bounded, north-up, aligned single-band numeric rasters and persisted slope analysis. The [raster rework](../design/raster-data-analysis-rework.md) specifies future bounded import, Data/Analysis workbenches and shared Web maps; it does not change the current workflow until implemented. The [foundation record](../design/lidar-library.md) retains storage and scientific invariants. Consult bd before claiming a slice.

Delivered on that branch: catalogue schema through v13 with the asset/chunk/region indexes in the paged read orders, per-layer lattice and opaque-base reference, backed by a pre-migration `VACUUM INTO` copy; the ordered-occurrence resolver; a sparse publication/undo path wired through `stage_import`, `render_decision_preview`, `apply_import` and `undo_import`; **retained source COGs as the only durable member payload**, prepared inside the owning job directory and promoted into the immutable store only at publication with a journalled, no-replace link whose catalogue references commit inside the publication transaction; **paged generation reads** (`GenerationChunkReader` pages ≤256 published, spatially intersecting records with a keyset cursor, releasing the catalogue lock before opening committed assets); **occupied-region review traversal** (bounded ordered streams for incoming regions and accepted-head records, deduplicated, so neither work nor metadata grows with the empty envelope); slope computed one 1024×1024 core+halo block per occupied chunk with sparse result/quality chunks; and a bounded native display transport with the `canopi-raster://` Desktop protocol adapter and a shared bounded tile cache. Sparse publication is the default for new imports; the interim admission envelope (25,000,000 cells in the resulting union) is enforced for **both** formats before review work and rechecked at Apply, so larger representative runs need the explicit test-only override.

The display reduction rule is complete: a power-of-two level is chosen from the sample's native displacement (2048 cells selects level 11, never a clamp), a reduced cell spans `[k·s, (k+1)·s)` with its centre at `(k+0.5)·s`, and a minified sample bilinearly interpolates the four surrounding cell means normalized over valid contributors. Whole-chunk cells use stored `sum`/`count` aggregates, sub-chunk cells share one bounded page read per chunk, and a footprint crossing chunks adds stored sums for enclosed chunks and reads only boundary chunks. Combined memory for a representative run is a sampled process tree (root plus descendants every 50 ms from an idle baseline), and a verdict requires a complete baseline plus at least one complete workload sample: an incomplete measurement is reported unavailable, never a passing budget.

Review jobs own their prepared bytes. Staging keeps each source COG inside `jobs/<job>/`, `staging.json` records a job-relative location that resolution refuses to escape, and review, restart and Apply read it there without re-preparation. Publication promotes it with a durable `promotions.json` intent journal and a same-filesystem no-replace link, then commits the asset and interpretation references inside the same transaction as the generation and head; anything the job created with no committed owner is rolled back, while reused assets, accepted history and analysis results are never deleted. An `awaiting_review` job survives a restart; a settled (failed or cancelled) job's directory is removed at settlement. General reclamation of *old* unreferenced published assets stays deferred and is not part of this cleanup.

Rust owns native raster work; TypeScript owns any newly required orchestration. No new Python raster tooling or wholesale Python removal. Existing unrelated repository tools remain in use. The forwarded bounded-generation assignment authorizes its isolated capacity fixtures after preflight, not new UI or other engines. Production limits move only after its whole-workflow gates pass.

Preserve originals and sidecars; prepare stripped inputs before native tiled reads. Keep zero/negative data, NoData and existing Float32 conversion semantics explicit. This first migration must not claim the later precision-preserving or fully bounded import contract. Full-grid composition and old limits stay until the next end-to-end foundation assignment passes its product gates. Faithful later UI work uses approved HTML revision `0e696722`; material departures require renewed user approval. The [collaboration protocol](../design/raster-rework/collaboration-protocol.md) retains main-agent architecture/review and user courier authority.
