# LiDAR implementation guide

Use this entry point for raster import, overlap review, the shared library, analysis, or LiDAR presentation. The current foundation admits bounded, north-up, aligned single-band numeric rasters and persisted slope analysis. The [raster rework](../design/raster-data-analysis-rework.md) specifies future bounded import, Data/Analysis workbenches and shared Web maps; it does not change the current workflow until implemented. The [foundation record](../design/lidar-library.md) retains storage and scientific invariants. Consult bd before claiming a slice.

The standard-COG design replaces the unimplemented bespoke encoding at `24fd1a56`. At reviewed `6a5130b3`, retained source COGs, complete display footprints/interpolation, paged tile queries and restored admission are wired. The ordered iterator and publication structure are retained; C1/C2 address collision ownership and journal-clearing errors. Correct the unsupported lifecycle evidence, then run the real Desktop workflow under the scope freeze. BG8 remains verified within its reviewed scope. Historical orphan reclamation is separate from mandatory job cleanup. Source-specific validity, composed NaN NoData and separate analysis quality remain fixed in design §3.

Delivered on that branch: catalogue schema through v13 with the asset/chunk/region indexes in the paged read orders, per-layer lattice and opaque-base reference, backed by a pre-migration `VACUUM INTO` copy; the ordered-occurrence resolver; a sparse publication/undo path wired through `stage_import`, `render_decision_preview`, `apply_import` and `undo_import`; **retained source COGs as the only durable member payload**, prepared inside the owning job directory and promoted into the immutable store only at publication with a journalled, no-replace link whose catalogue references commit inside the publication transaction; **paged generation reads** (`GenerationChunkReader` pages ≤256 published, spatially intersecting records with a keyset cursor, releasing the catalogue lock before opening committed assets); **occupied-region review traversal** (each source's occupied index read once as up to four constant-translated monotone streams, merged with the accepted head's ordered records and deduplicated globally, so ordering is structural and neither work nor metadata grows with the empty envelope); slope computed one 1024×1024 core+halo block per occupied chunk with sparse result/quality chunks; and a bounded native display transport with the `canopi-raster://` Desktop protocol adapter and a shared bounded tile cache.

Rust owns native raster work; TypeScript owns any newly required orchestration. No new Python raster tooling or wholesale Python removal. Existing unrelated repository tools remain in use. The current product-closure assignment authorizes the named repairs and isolated existing-UI smoke, not a new capacity campaign, new UI or other engines. Production limits remain unchanged.

Preserve originals and sidecars; prepare stripped inputs before native tiled reads. Keep zero/negative data, NoData and existing Float32 conversion semantics explicit. This first migration must not claim the later precision-preserving or fully bounded import contract. Full-grid composition and old limits stay until the next end-to-end foundation assignment passes its product gates. Faithful later UI work uses approved HTML revision `0e696722`; material departures require renewed user approval. The [collaboration protocol](../design/raster-rework/collaboration-protocol.md) retains main-agent architecture/review and user courier authority.
