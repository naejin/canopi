# LiDAR implementation guide

Use this entry point for raster import, overlap review, the shared library, analysis, or LiDAR presentation. The current foundation admits bounded, north-up, aligned single-band numeric rasters and persisted slope analysis. The [raster rework](../design/raster-data-analysis-rework.md) specifies future bounded import, Data/Analysis workbenches and shared Web maps; it does not change the current workflow until implemented. The [foundation record](../design/lidar-library.md) retains storage and scientific invariants. Consult bd before claiming a slice.

Engine, artifact and capacity findings live in the [Q receipt](../design/raster-qualification-q.md) and [GeoLibre reuse inventory](../design/raster-rework/geolibre-reuse-inventory.md). **Q is not qualified.** The existing Python harness under `scripts/raster-qualification/` still has independently reproduced gate defects despite its passing regression suite. The latest private-evidence distribution (one fail, eleven inconclusive) is implementer-reported, not independently accepted. Consult the [review/debrief](../design/raster-rework/review-and-debrief.md) for revision-linked evidence.

The accepted tooling direction is TypeScript for qualification orchestration/admission/verdicts and Rust for native raster operations. The decision path is now implemented in TypeScript under `scripts/raster-qualification/ts/` against the unchanged [C1–C8 contract](../design/raster-rework/q-admission-acceptance.md); see the [migration receipt](../design/raster-rework/q-typescript-receipt.md), the [standing review](../design/raster-rework/q-typescript-review.md) and the [assertion evidence map](../../scripts/raster-qualification/assertion_evidence_map.md). A source role claimed more than once is rejected rather than resolved by arrival order; every per-run observation is mandatory and a recorded over-budget value fails even when its record has a gap; each declared artifact needs its own version, integrity and license record, compared against the declared source pin rather than against the report's own claim; a sidecar must be observed present both before and after preparation, since equal hashes alone are not survival evidence; and the declared transport is the plan's scoped local bridge, so an HTTP-only measurement does not qualify bounded local access. It recomputes admission and verdicts from raw report and declaration bytes and owns the CLI exit; the runner's final step invokes it. Python is frozen legacy tooling; unrelated Python scripts are unaffected. Do not trust a serialized admission label or a green test suite as qualification, run private experiments without authorization, or start N1. The scientific requirements remain in [requirements.json](../../scripts/raster-qualification/requirements.json); a limitations string cannot waive them.

Retain measured candidate limitations without promoting them into route qualification: the inspected numeric decoder requires prepared tiled derivatives rather than stripped GeoTIFFs; N1 must provide a bounded legacy reader or prepare before numeric readability. GDAL remains the CRS authority; incomplete fixture WKT is not silently rewritten. No published Whitebox artifact matches the pinned source revision. The stream decoder requires guarded disposal, and the tested Whitebox WASI slope route was rejected for edge interpolation. Native GDAL preparation/slope are already allowed; a changed engine route still requires the user's decision. Material deviations from approved UI revision `0e696722` require renewed prototype approval.

The TypeScript path is implemented, not independently accepted: Round 2 review at `6a98cd33` still reproduced lost failures, a display false pass and source overwrite during input rejection. Use the [standing review](../design/raster-rework/q-typescript-review.md#round-2-independent-disposition) and [bounded design reassessment](../design/raster-rework/q-typescript-reassessment-agent-prompt.md). The previous two-round repair authority is exhausted; the user authorized diagnostics and a design proposal only, with implementation requiring approval after user-mediated independent review. Green aggregate tests or permanently blocked overall Q do not prove individual requirement verdicts are sound.

The library owns originals, masks, numeric results, jobs and caches; a Design owns only references and presentation. Shared workspace navigation never changes raster geography or scientific results. Use the current map/camera lifecycle rather than introducing a second map owner.

For native library changes, run the focused `services::lidar` tests and repository Rust gates. The real IGN lifecycle command and prerequisites are in the build guide; an unavailable fixture is not a pass. Frontend tests include `lidar-actions`, `lidar-library-store`, `lidar-map-presentation`, `design-edit-lidar`, and `lidar-camera-navigation` under `desktop/web/src/__tests__/`. Shared contracts require generated-binding checks; shared workspace changes require the edition gates in [AGENTS.md](../../AGENTS.md#quality-gates).
