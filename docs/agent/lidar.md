# LiDAR implementation guide

Use this entry point for raster import, the shared library, analysis, inspection and presentation. The repaired stack is integrated for user review; see the [current receipt](../design/raster-rework/completion-receipt.md#current-correction-acceptance) for verified scope and `canopi-j571.3` for remaining qualification. The [foundation record](../design/lidar-library.md) retains storage and scientific invariants. Consult bd before claiming implementation.

The [GeoLibre adoption plan](../design/raster-rework/geolibre-adoption-plan.md) is being delivered on `feature/geolibre-adoption`; the [adoption receipt](../design/raster-rework/geolibre-adoption-receipt.md) records each slice's evidence. The fixed-item library, upstream display route, Data Library and Layers data band have landed (S1–S3); contextual GeoLibre slope (S4) and whole-app qualification (S5) remain. Where this guide and older raster-rework records disagree, the adoption plan and this guide win. Sources keep the [ordered COG Data Layer](../design/raster-rework/ordered-cog-design.md) storage of [ADR 0027](../adr/0027-ordered-cog-data-layers.md): a topmost-valid composition of retained source COGs, now frozen after its first publication.

## Current implementation

- **Fixed library items.** `services/lidar/mod.rs` exposes `import_item`/`retry_import`/`dismiss_import` (one new item per import, saved request in `lidar_import_jobs.request_json`), `rename_layer`/`rename_analysis`, guarded `delete_layer` (refused while saved results depend on it) and `delete_analysis`. A published item refuses new sources; there is no history, source editing, library Undo or automatic refresh. Catalogue **v19** (`catalogue.rs`) adds import requests and result method/recipe columns, retires refresh attempts that already have a result, backs up with `VACUUM INTO`, and is refused by older binaries. Legacy history builders survive only as `#[cfg(test)]` migration fixtures.
- **Display derivatives.** `display_cog.rs` prepares content-keyed, DEFLATE, 256-block, AVERAGE-overview COGs (profile `display-cog-deflate256-v1`) per source asset or chunk-group part, stages them outside the asset scope and renames them into `$APPDATA/lidar/display-cog/`, registers them in `display_cogs`, and answers `lidar_display_descriptor` (Preparing/Ready/Unavailable/Failed/Stale, fenced by generation). Import prepares derivatives before publication; older items prepare lazily on the one preparation lane. NoData is the -2^127 sentinel, tagged with its exact decimal.
- **Retired display route.** The PNG pyramids, on-demand `tiles.rs` renderer, `tile_cache.rs`, `lidar_raster_tile` and the `tilesets` contract are gone; the library reclaims `display/` and `display-tiles/` on open. `raster_info.rs` keeps the two `gdalinfo` metadata helpers analysis still uses.
- **Numeric reads.** `generation.rs` (`CollectionReader`, `GenerationReader`) and `collection.rs` resolve bounded windows for analysis and inspection; `inspection.rs` samples one pixel through display admission (`admit_sample_request`). `admission.rs` keeps the unchanged 24-file/2-GiB/400M-cell import policy.
- **Frontend.** `maplibre/raster-display/` owns the upstream `maplibre-gl-raster` adapter and the two-lane worker pool (see [MapLibre](maplibre.md#lidar-raster-band)). `app/lidar/display.ts` owns descriptors and styles, `library-items.ts` the Data Library read model, `actions.ts` every library and reference mutation, `library-store.ts` the snapshot and polling, `inspection.ts` the inspection session. `components/panels/lidar/DataLibraryPanel.tsx` (with `LibraryPreview.tsx`) is the `data` side panel; `LidarLayersSection.tsx` is the Layers data band. There is no Analysis panel or navigation.

Q is unqualified and frozen. Preserve useful regression tests and [historical evidence](../design/raster-qualification-q.md); do not repair or rerun its retired harness assignments. The [review/debrief](../design/raster-rework/review-and-debrief.md) owns historical outcomes and improvement evidence. GDAL and the pinned native reader remain selected; Rust owns native raster work and TypeScript application orchestration. No new Python raster tooling or wholesale Python removal.

Preserve originals/sidecars, source-specific validity, valid zero/negative values and current Float32 semantics. The candidate retains its old 24-file/2-GiB/400M input policy; lift those limits only through the source-import amendment’s bounded implementation and evidence. Source-only publication no longer requires composed-pixel measurement; source facts remain measured during preparation. Legacy dense/sparse assets stay readable exactly; never reinterpret masked historical replacement as simple source order. [Collaboration](../design/raster-rework/collaboration-protocol.md) retains main-agent review and user courier authority.

The library owns originals, masks, numeric results, jobs and caches; a Design owns only references and presentation. Shared workspace navigation never changes raster geography or scientific results. Use the current map/camera lifecycle rather than introducing a second map owner.

For native library changes, run the focused `services::lidar` tests and repository Rust gates. The real-fixture ignored lane and its fixture variables are in the [build guide](build-release.md#lidar-raster-engine); a run without its fixtures is not a pass, and an unavailable fixture is reported as unavailable rather than as a green lane. Frontend tests include `lidar-actions`, `lidar-library-store`, `lidar-library-items`, `lidar-data-library-panel`, `lidar-layers-section`, `lidar-display`, `raster-display-pool`, `raster-display-adapter`, `design-edit-lidar`, and `lidar-camera-navigation` under `desktop/web/src/__tests__/`. Shared contracts require generated-binding checks; shared workspace changes require the edition gates in [AGENTS.md](../../AGENTS.md#quality-gates).
