# LiDAR implementation guide

Use this entry point for raster import, overlap review, the shared library, analysis, or LiDAR presentation. The current foundation admits bounded, north-up, aligned single-band numeric rasters and persisted slope analysis. The [raster rework](../design/raster-data-analysis-rework.md) specifies future bounded import, Data/Analysis workbenches and shared Web maps; it does not change the current workflow until implemented. The [foundation record](../design/lidar-library.md) retains storage and scientific invariants. Consult bd before claiming a slice.

Engine, artifact and capacity qualification for the rework lives in the [Q receipt](../design/raster-qualification-q.md), its harness under `scripts/raster-qualification/`, and the [GeoLibre reuse inventory](../design/raster-rework/geolibre-reuse-inventory.md). **Q is not qualified:** eligibility is decided by [`requirements.json`](../../scripts/raster-qualification/requirements.json) through `measure.py gate`. Against the current records the verdict is `inconclusive` for all twelve requirements, because the recorded reports carry no identity/provenance block; treat the receipt's measured subtests as findings, not as an accepted engine route. Evidence admission now compares each report's own recorded route, transport, environment, artifact and fixture identity against the declared route, and refuses to promote observations from a report that failed its own checks. The [gate repair](../design/raster-rework/q-gate-repair-receipt.md), [evidence-integrity](../design/raster-rework/q-evidence-integrity-receipt.md), [admission-completeness](../design/raster-rework/q-admission-completeness-receipt.md) and [declaration/precedence](../design/raster-rework/q-declaration-precedence-receipt.md) receipts record which review findings are repaired and which remain unimplemented. Admission now validates the declarations themselves before anything is indexed from them — a missing manifest or hash is a gap, while a malformed, duplicated or conflicting declaration is an evaluator-input failure that stops the CLI with a nonzero result — judges fixture coverage against the declared per-role manifest, requires each measured artifact to correspond to its declared source pin, requires a source run identity and a fresh recorded time under one injected clock, and collects every independently evaluable finding before reducing: a known conflict or recorded failure stays a failure even when an unrelated field, or the summary `result`, is missing. The [consolidated repair](../design/raster-rework/q-consolidated-repair-receipt.md) against the [C1–C8 acceptance contract](../design/raster-rework/q-admission-acceptance.md) extends this across the whole input-to-CLI path: report fields are shape-checked at the load seam so a malformed input yields a verdict instead of a traceback, boolean leaves accept only booleans, the plan's numeric budgets are enforced on sampled candidate records, the bundle gate requires an admission block and validates assertion verdict types before use, and the qualification runner's exit status is the requirement gate's rather than the experiment summary's. Run `python3 -m unittest discover -s scripts/raster-qualification/tests` before trusting any verdict from the harness. Read the receipt before planning bounded numeric access. Its load-bearing findings: bounded numeric and display access is qualified for **prepared tiled COG derivatives** only, because no candidate role range-reads a stripped GeoTIFF, so N1 must either prepare before a head becomes numeric-readable or supply a bounded legacy reader; GDAL is the CRS resolver, and the incomplete EPSG:2154 fixture WKT is neither rewritten nor resolvable by the candidate projection engine; no published `whitebox-wasm` artifact matches the pinned commit; the candidate stream decoder's `free()` is not idempotent, so the owning adapter must make teardown safe; and the Whitebox WASI `slope` tool is rejected for edge interpolation.

The harness is a qualification tool, not a production path. Its intended fail-closed contract is not yet independently accepted: the [consolidated review](../design/raster-rework/q-consolidated-admission-review.md) records remaining false passes and the runner's use of an experiment comparison rather than the authoritative requirement gate. A green harness suite is necessary but insufficient evidence of eligibility. The [stable admission matrix](../design/raster-rework/q-admission-acceptance.md) governs the pending repair. Do not infer Q acceptance from `compare` or `run_all_experiments.sh`, rerun private experiments without authorization, or start N1. A limitations string cannot waive a requirement.

The library owns originals, masks, numeric results, jobs and caches; a Design owns only references and presentation. Shared workspace navigation never changes raster geography or scientific results. Use the current map/camera lifecycle rather than introducing a second map owner.

For native library changes, run the focused `services::lidar` tests and repository Rust gates. The real IGN lifecycle command and prerequisites are in the build guide; an unavailable fixture is not a pass. Frontend tests include `lidar-actions`, `lidar-library-store`, `lidar-map-presentation`, `design-edit-lidar`, and `lidar-camera-navigation` under `desktop/web/src/__tests__/`. Shared contracts require generated-binding checks; shared workspace changes require the edition gates in [AGENTS.md](../../AGENTS.md#quality-gates).
