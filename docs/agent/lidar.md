# LiDAR implementation guide

Use this entry point for raster import, overlap review, the shared library, analysis, or LiDAR presentation. The current foundation admits bounded, north-up, aligned single-band numeric rasters and persisted slope analysis. The [raster rework](../design/raster-data-analysis-rework.md) specifies future bounded import, Data/Analysis workbenches and shared Web maps; it does not change the current workflow until implemented. The [foundation record](../design/lidar-library.md) retains storage and scientific invariants. Consult bd before claiming a slice.

Engine, artifact and capacity qualification for the rework lives in the [Q receipt](../design/raster-qualification-q.md), its harness under `scripts/raster-qualification/`, and the [GeoLibre reuse inventory](../design/raster-rework/geolibre-reuse-inventory.md). **Q is not qualified:** eligibility is decided by [`requirements.json`](../../scripts/raster-qualification/requirements.json) through `measure.py gate`, and the current verdict is non-pass. Treat the receipt's measured subtests as findings, not as an accepted engine route. The [gate repair receipt](../design/raster-rework/q-gate-repair-receipt.md) records which review findings are repaired and which remain unimplemented. Read the receipt before planning bounded numeric access. Its load-bearing findings: bounded numeric and display access is qualified for **prepared tiled COG derivatives** only, because no candidate role range-reads a stripped GeoTIFF, so N1 must either prepare before a head becomes numeric-readable or supply a bounded legacy reader; GDAL is the CRS resolver, and the incomplete EPSG:2154 fixture WKT is neither rewritten nor resolvable by the candidate projection engine; no published `whitebox-wasm` artifact matches the pinned commit; the candidate stream decoder's `free()` is not idempotent, so the owning adapter must make teardown safe; and the Whitebox WASI `slope` tool is rejected for edge interpolation.

The harness is a qualification tool, not a production path. Its verdicts are fail-closed and its tests are part of the gate: `python3 -m unittest discover -s scripts/raster-qualification/tests` must pass before any verdict from it is trusted. Eligibility comes from the requirement contract, not from counting passing experiments; a limitations string cannot waive a requirement. `bash scripts/raster-qualification/run_all_experiments.sh` reruns every experiment and exits non-zero unless the aggregate qualifies.

The library owns originals, masks, numeric results, jobs and caches; a Design owns only references and presentation. Shared workspace navigation never changes raster geography or scientific results. Use the current map/camera lifecycle rather than introducing a second map owner.

For native library changes, run the focused `services::lidar` tests and repository Rust gates. The real IGN lifecycle command and prerequisites are in the build guide; an unavailable fixture is not a pass. Frontend tests include `lidar-actions`, `lidar-library-store`, `lidar-map-presentation`, `design-edit-lidar`, and `lidar-camera-navigation` under `desktop/web/src/__tests__/`. Shared contracts require generated-binding checks; shared workspace changes require the edition gates in [AGENTS.md](../../AGENTS.md#quality-gates).
