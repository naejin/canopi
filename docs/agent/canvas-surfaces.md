# Canvas surfaces and construction

Part of the [Canvas runtime guide](canvas-runtime.md). Read this guide for public seams. For persistence across runtime lifetimes, use [Document lifecycle](document-lifecycle.md).

## Public Seams

- App code must not reach into renderer implementations or runtime internals.
- The app-facing canvas boundary is split into `CanvasCommandSurface`, `CanvasQuerySurface`, and `CanvasDocumentSurface`.
- `CanvasCommandSurface` is role-shaped: `tools`, `viewport`, `history`, `sceneEdits`, `chrome`, `layers`, `plantPresentation`, and `speciesFocus`. New focused callers should consume the narrow role surface exported by `canvas/session.ts` instead of the full command bundle.
- The App Command Graph may consume the full `CanvasCommandSurface` because it is the shared command-ID orchestration layer. Do not use that as precedent for ordinary UI components or leaf controllers.
- Toolbars, shortcuts, menus, and plant color actions consume command surfaces through the narrowest role that covers their writes.
- `app/canvas-commands/` owns the platform-neutral Canvas toolbar command catalog and caller-shaped projection: the exact 2/6/2 tool groups, tool/history/settings command identity, resolved labels and descriptions, shortcuts, active/disabled/pressed policy, and typed intents. Desktop adapts that catalog into the App Command Graph; Web Edition builds the same projection from browser-safe runtime facts. Keep Tauri, Web modules, platform entries, IPC, storage, and shell controllers outside this module; icons and Plant Color/Plant Symbol popovers remain presentational toolbar concerns.
- A disabled projected command must not dispatch. Edition adapters must also re-read the live Canvas command surface when an admitted action runs so a retained DOM handler cannot target a detached runtime; do not close over a rendered command surface for later mutation.
- Canvas command shortcut definitions keep display text separate from valid `aria-keyshortcuts` tokens and match Ctrl/Meta, Shift, and Alt exactly. The Web composition root installs the browser-safe `web/canvas-shortcuts.ts` listener; that module owns replacement, disposal, editable-target suppression, live-surface dispatch, and Vite HMR cleanup. Do not route Web shortcuts through the Desktop App Command Graph.
- Document session orchestration, save/load, chrome, resize, and teardown consume document surfaces. `CanvasDocumentSurface.attachInspectionTo()` returns a disposable read-only lens handle; `SceneCanvasInspectionOwner` owns its renderer, subscriptions, observer, animation frame, independent inspected location, and hover cleanup. Both edition components use that surface. Document replacement resets the independent inspected location; runtime destruction releases mounted lenses.
- Sibling read-only surfaces consume query surfaces for scene snapshots, the viewport snapshot signal, selection reads, placed plants, localized names, and presentation context.
- `CanvasQuerySurface.getDesignObjectSelection()` is the app-facing read model for editable top-level Design Object selection, selected locked Design Objects, blocked selection reasons, and combined visual bounds. New selection actions, transform overlays, lock cues, and toolbar placement should consume this query instead of duplicating plant Visual Footprint, annotation bounds, Zone bounds, Layer, Object Group, or Design Object Lock rules.
- Publish live canvas sessions as explicit `CanvasRuntimeSurfaces` bundles. Do not publish a raw `SceneCanvasRuntime`, and do not cast a role-specific fake into the session signal; tests should use `createTestCanvasRuntimeSurfaces()` with the role surface they need.
- `createCanvasRuntimeSurfaces()` must compose `runtime.commandSurface`, `runtime.querySurface`, and `runtime.documentSurface` directly. Do not reintroduce fallback casts that treat `SceneCanvasRuntime` itself as any role surface.
- Scene and localized Plant-name freshness for app callers is exposed through `CanvasQuerySurface.revision`. Do not recreate canvas runtime mirror revision signals; app modules subscribe through the query surface instead.
- Exactly one `WorkspaceCameraOwner` is admitted into a `SceneCanvasRuntime`. The owner exposes separate frame-read and navigation roles; runtime readers and tools receive only `WorkspaceCameraFrameReader`, while navigation paths receive the command role. `CameraController` is the standalone fallback adapter. The owner atomically publishes one immutable viewport, CSS screen size, active-surface device-pixel ratio, reference scale, and monotonically increasing revision; no-op camera mutations keep the same snapshot and revision. Screen coordinates and viewport offsets are always CSS pixels. One runtime-owned effect converts every published frame, including an external map move, into viewport rendering, chrome, and overlay refresh; teardown removes that effect before disposing the owner. `CanvasQuerySurface.viewport` forwards the exact frame signal for app callers. Do not mirror viewport facts or revisions into Scene Session state, global signals, or query aliases.
- `canvas/runtime/scene-interaction.ts` is the sole DOM pointer owner for an admitted workspace sequence. It publishes the matching pointer record before attempting container capture, retains window capture listeners as delivery fallback, and records only successful container capture. It fences that record before explicit release, so release-generated `lostpointercapture` cannot cancel a committed edit. Matching unexpected loss, `pointercancel`, Escape, blur, tool change, document replacement, and disposal cancel once; stale loss and competing pointer IDs do nothing. Capture acquisition or release failure must leave the same cancellation and window-delivery path usable. Do not add a second input broker or map gesture owner. Physical two-contact pinch and `touch-action` policy remain unqualified.
- Temporary bounds navigation belongs to that camera owner. `focusTemporaryBounds()` fits validated local-metre bounds with caller-supplied CSS-pixel padding and an optional scale ceiling, retaining only the first pre-focus viewport; `returnFromTemporaryFocus()` restores and consumes it. Initialization, successful document load or replacement, and disposal clear the bookmark. A replacement rejected before hydration retains it because the current Design and runtime remain authoritative. Keep this transient state out of Scene history and document persistence.
- `maplibre/workspace-camera.ts` is the low-level map-backed owner. It retains the same frame signal while detached or attached, sends navigation only to the active MapLibre map, publishes frames from live MapLibre projection, and transfers the last valid local-metre viewport across attach, detach, replacement, and failure. Its attachment control does not own map construction or removal. The shared workspace composition owns it; do not wire a second camera synchronization effect around this owner.
- `app/canvas-map-surface/workspace-activation.ts` is the internal transactional admission seam for the shared workspace. `activate(snapshot)` gives each Design/map generation immutable session/spatial facts, an owned latest basemap presentation, and an optional maximum world extent. Its live `updateBasemapPresentation()` delegates only to the current MapLibre controls attempt, so opacity/style/visibility changes never create a camera, custom layer, or Scene runtime resource. It admits the Scene runtime only after the first Surface Adapter-backed map, its public WebGL2 context, the canonical attached custom layer, and the camera are ready; initial admission failures release the attempted map before initializing Canvas2D. Design replacement cleans only the old map generation in restorer/watchers, camera, layer, map order, then connects the new generation to the existing Scene runtime and `MapLibreSceneRendererBridge`. The bridge's retained-snapshot replay is the only scene handoff between maps. Runtime initialization is shared across generations and runs once; only public final teardown joins pending cleanup/initialization and destroys it. Replacement failure after initialization uses the runtime's internal `reportRendererFailure()` once to replace only `maplibre-pixi`, republish the complete current Scene through Canvas2D, and leave the shared backend terminal for that coordinator. Latest-request and generation fences prevent stale map, style, camera, initialization, or failure callbacks from affecting a successor. Keep runtime failover out of `CanvasRuntimeSurfaces`; edition roots receive only the composition surface.
- `app/canvas-map-surface/workspace-runtime-composition.ts` is the app-owned construction seam for the shared workspace. It owns exactly one camera, shared renderer composition, Scene runtime, activation coordinator, reconciler, and wrapped document role surface; command/query roles remain the runtime’s existing surfaces. `WorkspaceRuntimeMountOptions` is the only edition-facing mount contract. `desktop-workspace-runtime.ts` and `web/browser-workspace-runtime.ts` bind their app, panel-target, and contribution adapters without importing the other edition. `start()` reconciles a nullable Design snapshot, initializes the sole viewport when a Design becomes active, and subscribes to live basemap and contribution snapshots; `dispose()` removes that subscription and joins terminal reconciliation. The required contribution adapter reads through the supplied Canvas query role, binds immutable LiDAR/terrain/Target presentation plus precision/diagnostic inputs to the Design session identity, and never exposes a map to stores or UI. Optional `onMapStateChange` observes readiness, terrain errors and precision. Edition lifecycles must await `start()` before rulers or Design attachment, and must synchronously hand off the Design before observer, settings, and composition cleanup.
- `app/canvas-map-surface/workspace-generation-reconciler.ts` is the app-owned bridge from synchronous `CanvasDocumentSurface.replaceDocument()` to workspace activation. Its synchronous fence returns an opaque replacement ticket; only that ticket can queue the authoritative snapshot read after successful replacement or `CanvasDocumentReplacementNotAdmittedError`, so an older reentrant caller cannot reconcile a successor that remained fenced. The coordinator, rather than the reconciler, joins retained cleanup before a replacement activation. Snapshot equality includes opaque session identity, so an equal map for a new Design still replaces while repeated publication for the same admitted identity is inert. Busy or other non-admission failures remain fenced; disposal and successor replacement invalidate queued predecessor work.
- `canvas/runtime/runtime.ts` owns the app-facing Canvas Runtime Surface interfaces. `canvas/runtime/surfaces.ts` only composes the live runtime surfaces; command, query, and document surface behavior belongs behind the role modules in `canvas/runtime/*-surface.ts`.
- `SceneCanvasRuntime` may still wire the concrete scene runtime during migration, but new surface behavior should be added to the relevant role module before adding more broad runtime pass-through code.
- `canvas/runtime/scene-runtime/construction.ts` owns concrete runtime construction: SceneStore, the single injected or fallback `WorkspaceCameraOwner`, SceneHistory, the Settled Scene Authority, RendererHost, presentation, document bridge, mutation controller, and command/query/document role surface assembly. It returns only a `SceneStateReader`, a session-only writer, and edit/admission roles to the `SceneCanvasRuntime` shell; never leak the concrete Store or the full multi-role authority through the construction result. Keep new construction and disposal wiring behind that module instead of expanding `SceneCanvasRuntime`.
- `canvas/runtime/document-surface.ts` owns document lifecycle surface behavior for load, replace, exact persistence capture, viewport initialization, chrome attachment, resize, and teardown. Its document authority state is `absent`, `settling`, or `loaded`: once hydration begins, `hasLoadedDocument()` remains true even after a late failure, while persistence capture reports typed `document-settlement` busy until the retained hydration succeeds. A coordinator-issued `CanvasDocumentReplacementNotAdmittedError` is the sole exception: hydration never began, so the surface restores its prior document state and the old Scene remains captureable. This prevents store-only fallback from hiding an already accepted Scene. `SceneCanvasRuntime` compatibility methods delegate to that role.
- `canvas/runtime/lifecycle-owner.ts` owns the single Desktop, Web, or UI gallery runtime lifetime lease. `acquireCanvasRuntimeLifecycle(releaseRuntime)` is the only admission API: it awaits a previously requested release before atomically reserving the next lease, and rejects an unreleased live owner. `releaseRuntime` and `lease.release()` return promises; repeated release calls join one attempt, ownership clears only after it resolves, and a rejected loss-prevention handoff remains retryable before another runtime may mount. After handoff succeeds, component cleanup must exhaust every remaining independent cleanup and release this lease even when a non-authoritative cleanup reports an error. Desktop and Web mount the shared workspace composition through separate sequencing adapters because their attachment, first resize, auxiliary cleanup, and persistence handoff ordering differ; the assessed ownership map and focused tests live in [Document Lifecycle](document-lifecycle.md#canvas-host-lifecycle-assessment).
- `canvas/runtime/query-surface.ts` owns read-only surface behavior for scene snapshots, viewport facts, revisions, selection, placed plants, localized names, and plant presentation context. `SceneCanvasRuntime` compatibility methods delegate to that role.
- `canvas/runtime/command-surface.ts` owns command surface behavior for tools, viewport changes, history, scene edits, chrome toggles, layer edits, and plant presentation writes. `SceneCanvasRuntime` compatibility methods delegate to that role.
- `SceneCanvasRuntime` is the compatibility shell for initialization, interaction attachment, and private callbacks used by construction; it should not regain role-surface dependency assembly or low-level constructor wiring.
- `canvas/runtime/host.ts` is the generic wrapper used by tests and the UI gallery when they need a standalone `SceneCanvasRuntime`. Production Desktop and Web roots mount `WorkspaceRuntimeComposition` through their edition factories and must not add another runtime host beside it.
- `web/browser-canvas-runtime.ts` owns only Web's browser-safe `CanvasRuntimeAppAdapter` presentation capabilities. It must stay free of Tauri IPC, desktop document lifecycle, the command graph, and native Saved Object Stamp import/export paths.
- `components/canvas/LayerPanel.tsx` is a shared presentational layer view. Desktop `components/panels/LayersPanel.tsx` supplies scene/map/terrain actions; `web/WebLayersPanel.tsx` supplies only the four rendered Scene layers. Keep native imports in the Desktop adapter, never in the shared view or Web workspace. Unsupported location/terrain capabilities remain absent.
- `canvas/runtime/app-adapter.ts` owns the runtime-facing `CanvasRuntimeAppAdapter` contract and detached fallback behavior. The production adapter optionally supplies the Design Session history participant and shared sequence/branch coordination; detached runtimes retain their local Scene sequence. Optional capabilities stay absent when unsupported; do not install no-op adapters that make contextual UI advertise unavailable behavior.
- `app/canvas-runtime/app-adapter.ts` is the single platform-neutral production factory for app-owned clean state, Design composition, translation, settings reads and writes, signal subscriptions, and Layer projection. Edition roots supply only presentation data and optional Saved Object Stamp capture.
- `app/canvas-runtime/desktop-adapter.ts` supplies IPC-backed `CanvasPlantLabelResolver` and `CanvasSpeciesCache` plus the live Saved Object Stamp Workbench. `web/browser-canvas-runtime.ts` supplies detached presentation data and omits stamp capture until Web has a real capture workbench; the runtime hides stamp actions when that capability is absent.
- `canvas/runtime/presentation-data.ts` owns the runtime-facing Species presentation interfaces. Production presentation-data sources should enter construction through `CanvasRuntimeAppAdapter.presentationData`; explicit constructor overrides are test seams, not edition composition.
- Production files under `canvas/runtime/` must not import `app/**`; add behavior through `CanvasRuntimeSurfaces`, `CanvasRuntimeAppAdapter`, or a narrower runtime-owned interface instead.
