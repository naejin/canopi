# Canvas rendering and camera presentation

Part of the [Canvas runtime guide](canvas-runtime.md). Read this guide for rendering ownership, text visibility and zoom. For persistence across runtime lifetimes, use [Document lifecycle](document-lifecycle.md).

## Rendering Ownership

- [Canvas performance](canvas-performance.md) documents retained geometry, frame-coalesced scheduling, local benchmarks, and optional native renderer trace capture.

- `renderers/capabilities.ts` probes each incompatible context type (`2d`, `webgl`, `webgl2`) on an independent HTMLCanvasElement or OffscreenCanvas: creating a context locks that canvas to its type. Capability regression tests must model that lock and exercise automatic RendererHost selection with the real backend support predicates; injected capability booleans alone cannot verify detection. Context/constructor failures remain unsupported capabilities so fallback can proceed.
- `RendererHost` owns backend lifecycle, capability probing, fallback, and pending backend initialization cancellation. It publishes the shared initialization Promise before invoking backend code, admits exactly one active or pending initialization, and rejects repeated or callback-reentrant initialization until disposal; `run()` joins the one pending initialization instead of selecting a second backend. The render scheduler publishes its container only after that exact initialization succeeds. Concurrent operations that fail on the same active backend join one runtime failover, dispose that backend once, and share the selected successor. A default retried operation quarantines every backend on which it fails and continues through the supported candidates until one succeeds or exhaustion leaves no active backend; queued work must join an already-admitted failover rather than execute on its fenced predecessor. Backend-failure observers are telemetry only: report their exceptions, but never let them interrupt fencing, disposal, or successor selection. Every `run()` revalidates both lifecycle epoch and backend identity after awaiting initial acquisition or failover, before invoking caller code and again after caller completion; stale success or failure cannot escape, record failure against, or trigger fallback in a reinitialized lifecycle. Disposal invalidates its lifecycle epoch synchronously and permits a new initialization even while the obsolete backend finishes cleanup; a backend instance returned by the older initialization must dispose itself and may never become active, publish a backend change, or trigger fallback after teardown. Backend-change publication is part of initialization settlement: recheck lifecycle currency after the callback, and roll back the installed backend when the callback throws or reentrantly disposes the host. Fire-and-forget render-scheduler invalidation and resize paths must terminate expected lifecycle-cancellation rejections during teardown and report other renderer failures.
- `SceneRuntimeConstructionOptions.renderer` is the production composition seam through which the shared workspace provides MapLibre Pixi followed by Canvas2D fallback and observes backend changes. Do not expose this choice as a product toggle.
- `canvas/runtime/renderers/maplibre-scene.ts` bridges Scene Runtime snapshots to one map-owned render target. It owns no canvas, graphics resources, resize observer, ticker, or frame callback. A target connection is generation-fenced so teardown from an obsolete map cannot disconnect or fail its replacement. Target failures surface on the next RendererHost operation and use normal runtime failover. The workspace lifecycle must remove the failed custom layer from presentation in its backend-change callback before the retried Canvas2D draw becomes visible.
- The app-owned `canvas-map-surface/workspace-document-surface.ts` wraps a `CanvasDocumentSurface` only for `replaceDocument()`: it synchronously requests a shared-workspace generation disconnect before delegating the unchanged Scene replacement. It must not add map policy to runtime document authority or disconnect for loading, persistence, chrome, viewport, resize, or destruction.
- Renderers are projections of scene state, never the source of truth.
- Each renderer owns one `SceneViewportPresentation` for its retained snapshot and admitted plant labels. Full scene updates replace that projection; camera-only pans translate cached labels without geometry/admission work, while zooms reproject through the same `projectScenePlantLabels` used by initial runtime presentation. Dispose releases retained data. Keep this policy shared; Pixi and Canvas2D retain their own drawing resources and no additional snapshot mirror.
- Pixi renders physical Zones/Measurement Guides under the camera transform, and Plant Symbols, stack badges, Annotation text/markers/outlines, and labels in CSS-pixel presentation layers. Use shared screen points and footprints so rasterized fonts and tessellated curves never start as tiny world-unit primitives. Pixi backing resolution follows detected device density, like Canvas2D. Preserve CSS color alpha when converting color channels to Pixi values; Zone Layer opacity and the existing fill/interaction alpha still compose. Canvas2D Zone stroke width divides by camera scale only, never device-pixel density.
- `SceneRendererSnapshot` is a total projection contract. Presentation supplies an explicit nullable typed hover target and derives every per-kind selection collection from typed Scene Session targets before calling a renderer; renderers and renderer tests must not infer kind from raw IDs or omitted fields. `selectionLabelPlantIds` is a deliberately narrower projection and is non-empty only when the whole typed selection is exactly one direct Plant.
- Camera transforms go through `WorkspaceCameraFrameReader`; its snapshot signal owns transient viewport observation and revision publication. Navigation goes through the paired owner command role. The zoom percentage uses a fixed reference of 20 CSS px per design meter (100%), independent of window size. Initialization and Design opening retain their existing framing behavior; they do not force a 100% view.
- `canvas/workspace-camera-policy.ts` is the shared zoom contract. It maps the MapLibre zoom range 0–27 into local-metre scale at the Design latitude, derives a bearing-aware single-world effective minimum for the current screen, and enters overview strictly below 0.1 CSS px per design metre. Camera mutations clamp before anchor compensation; exhausted inputs are exact no-ops that retain the frame object and revision. A successful Design replacement installs its generation policy and clears temporary return state; Canvas2D fallback retains the last accepted frame and matching policy.
- [Automatic Detail and the Inspection Lens](dense-canvas.md) are shared production behavior in both editions. The original density prototype and planting-strip option are retired.
- The in-canvas basemap and botanical scene share the production MapLibre workspace. The custom-layer bridge is the Pixi backend, with Canvas2D retained as the fallback backend under the same runtime and camera authority.
- Screen-space chrome such as rulers stays outside the world renderer. `canvas/rulers.ts` owns the complete ruler/scale overlay lifetime: its DOM, per-owner theme palette, latest atomic Camera snapshot, at-most-one active drag, document/window listeners, exact cursor restoration, screen-to-world guide conversion, construction rollback, and terminal idempotent teardown. Scene Chrome may compose grid/guide rendering around that owner, but must not expose ruler DOM parts or reconstruct renderer-shaped viewport adapters.
- Overview is a workspace presentation mode, not document state. Its renderer snapshot omits authored objects, names, selection decoration, grids, guides and local rulers without mutating Scene/settings; returning to site scale rebuilds presentation from the latest authoritative Scene. Inspection Lens and PDF projections remain independent. Confirmed geographic overview may show a ground-resolution scale bar; provisional or map-unavailable overview must not imply geographic scale.
- Strokes, outlines, stack badges, labels, handles, and measurement text are readability aids. Keep their visual weight screen-readable across zoom instead of scaling them as physical design geometry.
- Canvas2D scene presentation expresses screen-space coordinates and sizes in CSS pixels. Enter screen space through the renderer's shared device-pixel-aware transform; never replace it with a literal identity transform on a density-scaled backing store. Renderer coverage for screen-space presentation must include fractional or high device pixel ratios and viewport-only updates.
- Selected, hover, locked-object hover, and locked-Layer hover strokes are screen-space interaction cues owned by `scene-visuals.ts`. Pixi and Canvas2D renderers should consume the same interaction visual helper so selected states remain stronger than hover and locked states do not imply editable selection.
- Canvas notice placement uses the Canvas Notice Layout seam for safe screen-space slots. Active Tool HUDs use the top-left safe slot; Location Notices use the bottom-left safe slot and reserve the scale bar before compacting.
- Use scene invalidation for content, selection, presentation, locale, theme, and hover changes.
- Use viewport invalidation for pan, zoom, and fit operations.
- Use chrome invalidation for rulers, grid, and guide-only changes.
- Do not route viewport-only work through the full scene render path.
- `renderScene()` refreshes scene/presentation/selection; `setViewport()` is for camera-only updates. Both retain unchanged Pixi geometry. `resize()` only changes backing dimensions and must be followed by a scene or viewport render.

## Text Visibility And Zoom

- Zoom controls display localized **Overview** below 0.1 CSS px per design metre, retain fractional percentages below 1%, and disable commands at the effective limits. **Return to Design** fits ordinary content when that result is site scale; otherwise it centres Design origin at the standard empty-design framing. The overview marker is the screen projection of origin `(0, 0)`, appears only while on-screen, labels provisional placement without claiming confirmed geography, and invokes the same command.
- Pixi text is created through a renderer-owned factory at twice the renderer's device pixel ratio. The extra text texture samples preserve glyph edges during fractional pan/zoom positions and rotation; keep font sizes and transforms in CSS pixels, and keep texture resolution independent of camera zoom. Apply this to Annotations, measurement labels, pinned names, selection labels, and stack counts. The canvas backing store retains normal device density. Compare actual Pixi and Canvas2D output at DPR 1, fractional DPR, and DPR 2 when changing this policy; mocked text objects alone cannot expose texture filtering blur.
- `text-visibility.ts` owns the shared opacity curve for Annotation text and Pinned Plant Names: smoothstep from hidden at 8 CSS px per design meter to fully visible at 20. Font sizes stay screen-readable. Fading and selection are transient presentation; they must not change authored content, pinning, history, or dirty state.
- Screen fading applies only to the interactive canvas. Canvas PDF uses physical Automatic Detail for marks and preserves authored text through complete readable detail coverage or explicit retention; do not reuse screen fading to suppress printed text. See [ADR 0024](../adr/0024-shared-canvas-pdf-export.md). The [Canvas PDF guide](canvas-pdf.md) documents the settled print projection and selected shared encoder. Historical evaluation code remains isolated.
- One directly selected Plant or Annotation bypasses fading and collision suppression; hovering an Annotation also reveals its text. Mixed, multiple, and Object Group selection follow the fade. Renderer snapshots project `selectionLabelPlantIds` and nullable `revealedAnnotationId` from the whole typed selection; never infer this exception from expanded per-kind selected IDs. A pinned Plant reveals its name without a duplicate Selection Label. An unpinned Plant retains its existing Selection Label.
- Annotation creation/editing uses the existing readable DOM editor. Inline editing first selects the Annotation, preserving its readable renderer presentation across navigation.
- `annotation-layout.ts` owns Annotation presentation and geometry. An upright 8px note marker with a 1.5px stroke crossfades with text at the authored anchor. At scales where text could appear, collision rejection uses a quieter 4px square with a 1px stroke at half opacity. Below half text opacity, marker geometry drives hit testing, band selection, outlines, selection/group bounds, and placement previews; at or above half opacity, rotated text geometry does. Pointer hits have 4px allowance around a marker; band/visual bounds use the currently visible marker footprint. Coincident markers follow existing topmost scene hit order.
- Fit to content deliberately uses full authored rotated text bounds at every scale through `getAnnotationWorldBounds`, so framing is stable when the marker/text transition is crossed. Interactive geometry uses the explicit `getAnnotationVisualWorldBounds`/`Corners` helpers instead. Physical extent still uses Annotation anchors.
- Both Pixi and Canvas2D apply Layer visibility/opacity and refresh text/marker presentation on viewport-only updates. Marker discovery follows existing object/Layer lock rules. Hidden text must not intercept clicks outside its visible marker or reveal hidden-Layer content.
- The [dense Canvas guide](dense-canvas.md) owns footprint, collision, and Measurement Guide label rules. Zone Measurements, rulers, and the scale bar retain their existing visibility rules.
