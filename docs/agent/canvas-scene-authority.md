# Canvas scene authority and history

Part of the [Canvas runtime guide](canvas-runtime.md). Read this guide for scene ownership, history and dirty state. For persistence across runtime lifetimes, use [Document lifecycle](document-lifecycle.md).

## Scene Ownership

- `SceneStore` owns canvas scene state: plants, zones, annotations, groups, Design Object locks, layers, plant species colors, plant species symbols, species code reservations, selection, hover, Species Focus, and plant presentation state. Transient viewport state belongs only to the active `WorkspaceCameraOwner`.
- `SceneStore.persisted` returns a defensive clone on every read, including a fresh Plant array. Array-identity caches do not survive separate reads. `plant-spacing.ts` keeps the immutable-array fast path and shares indices across up to four recent geometries using exact ordered coordinate comparison. Cached coordinates are owned copies; metadata changes can reuse spacing, while position/add/remove changes miss the geometry cache. Keep snapshots immutable during a spacing-query operation, and preserve defensive-copy authority. See [native profiling evidence](../native-canvas-performance.md).
- Empty Scene construction clones the generated Layer catalog from `common-types/canopi-new-design-defaults.json`. Keep whole-document New Design composition in the Desktop and browser document seams; Scene defaults consume only Layer facts.
- Scene Design Object identity is always the immutable typed pair `{ kind, id }`; the neutral definitions and identity helpers live in `canvas/runtime/scene/design-object-targets.ts`, not in a kind-specific grouping or interaction module. Plant IDs, Zone names, Annotation IDs, Measurement Guide IDs, and Object Group IDs are not globally unique across kinds. Scene Session stores `selectedTargets` and `hoveredTarget`; commands, history patches, queries, interaction hit results, locks, and renderer presentation must preserve the pair and must never infer kind by searching a raw ID in a preferred order.
- Chrome reads `SceneStore.guides`, an owned copy of only the guide list. Map precision uses `CanvasQuerySurface.getScenePhysicalExtentMeters()`, which computes the current scalar extent directly inside SceneStore. These narrow reads never expose authoritative collections or cache across edits; keep the full defensive snapshot API for callers that need geometry.
- Selection and print queries reuse one defensive persisted snapshot for geometry and Plant presentation within the synchronous read. `createPlantPresentationContext(scale, plants)` accepts that snapshot’s Plant array; omit it only when the caller has no snapshot. Empty selection queries return fresh empty results without reading persisted state. Never retain this snapshot across calls, edits, or async work: selection queries must observe live previews, while print capture stays behind settled-read admission.
- `CanvasQuerySurface.getSelection()` returns an owned typed-target snapshot. The app-level `selectedObjectIds` signal is intentionally a lossy UI notification mirror: it projects only raw IDs for legacy reactive chrome and may collapse cross-kind collisions, but it must still publish when typed membership changes without changing that raw projection. Never read it as selection authority or use it to derive mutation targets, selection counts, hover, locks, history, or renderer state.
- Store mutators expose temporary mutable drafts only for the duration of their callback. `SceneStore` must clone the completed persisted or Session draft before installing it so a retained draft, nested entity, or collection cannot mutate authoritative state after admission closes.
- `SceneStore` is also the live-preview read model during a direct-manipulation gesture. `SceneRuntimeEditCoordinator` in `scene-runtime/transactions.ts` is the Settled Scene Authority: it exclusively admits persisted Scene and selection commands, records Scene history, replays undo/redo, applies presentation backfills, and hydrates documents.
- Consumers receive narrow authority roles for Scene Edit transactions, settled-command admission, settled observation, history, presentation maintenance, document hydration, or persistence capture. Read-side tools receive `SceneStateReader` or `SettledSceneReader`, never the concrete `SceneStore`. `SettledSceneReader.readWhenSettled()` only observes admission and returns its busy value; it must not flush maintenance or recover retained commands. Query surfaces and computed command availability such as undo/redo and paste must use that observational role, not `SceneCommandAdmission`. Keep the concrete authority and Store confined to runtime construction/authority ownership; do not pass `SceneCommandAdmission`, `SceneHistory`, or raw persisted Scene writers to query modules.
- Exactly one authority operation may be open or finalizing: a Scene Edit, one exact undo/redo replay, document hydration, or reserved document replacement. Immediate edits return busy without invoking their callback, a second long-lived begin raises `SceneEditBusyError`, history availability is false while busy, and whole commands must cross `runWhenSettled()` before reading live preview state or changing clipboard/selection state. Retained settlement recovery is a separate quarantined admission step: it must report the current command busy/false and must never use a broad history type as identity or success for a later command. Command callers may request pending immediate settlement retry; read-only/computed callers must not. Do not expose or perform a separate public active-edit check followed by a raw Scene write.
- Abort restores only persisted Scene state and transaction-owned selection. Camera viewport, hover, app-owned active Layer settings, and other transient presentation state may continue changing during a live preview and must not be rewound by abort.
- A failed abort remains admitted and retryable. A commit failure before history accepts the transaction may abort to its before-snapshot; once history accepts it, later projection, revision, and render publication retries must finish that committed outcome without recording twice or permitting the opposite rollback. Immediate commands retain an authority-owned retry handle so a failure cannot strand an inaccessible transaction.
- Tool and command cleanup that is valid only after a changed commit must use the transaction's `onCommitted` continuation. The authority runs that continuation after every other commit publication phase and before releasing ownership, and retries it with the retained transaction after failure. Keep continuations idempotent because an exception can occur after a continuation has made a partial external change. After a successful continuation, the authority performs a separate retryable deferred-backfill drain before release; a backfill enqueued by the continuation must not remain hidden in the queue or cause the continuation to run twice when publication retries.
- Undo/redo cursor movement, Scene patch replay, projection synchronization, revision publication, and invalidation form one staged authority settlement. A failure keeps the same history entry admitted; retry must not replay a different entry or expose partially restored state to another command.
- Scene history entries reserve their sequence from the Design Session participant when the production app adapter supplies one. The Canvas history command compares the next Scene and document sequences, undoing the greatest and redoing the smallest. New Scene and document entries announce a shared branch so redo is discarded in both participants. Scene replay remains inside Settled Scene Authority; document replay changes only its declared Design field and then invalidates Scene presentation.
- UI mirrors such as selection, Layer settings, guides, and Plant species colors synchronize as an idempotent authority settlement phase after commit or restored abort. Do not publish those mirrors from inside a speculative transaction callback or from a command after `run()` returns.
- Presentation metadata backfills use opaque authority tickets containing document generation, authoritative content revision, and per-Plant Canonical Name/presentation lineage. Defer current tickets while authority or backfill publication is busy, apply them after abort/no-op settlement, and drop them after changed commit, undo/redo, or document hydration makes them stale. Revision/invalidation publication is part of the reactive authority lifecycle: its callbacks must not re-enter a Scene command, and settled readers must be republished when maintenance finishes. Commit continuations and replacement finalizers run while authority remains admitted, so drain again after those callbacks before release. Render-time asynchronous presentation refresh prepares cache results without publishing query revisions or Scene backfills; `SceneRuntimeRenderScheduler` checks its container/epoch after preparation, then publishes the prepared render synchronously, and checks again before rendering. Plant-name cache preparation uses a monotonic prepared/published revision, so a newer cached refresh can publish an unpublished change when the refresh that populated labels becomes stale. Publication reports whether it advanced that revision; command owners must include that result in return and scene-invalidation semantics even when their cache result otherwise says unchanged. If a later Species-cache stage fails, retain the prepared label progress: an active command owner publishes and invalidates it before surfacing the failure, while render preparation skips unavailable backfills and renders the label-enriched snapshot without creating a fire-and-forget rejection. A stale or destroyed owner must publish nothing. Disposal invalidates the render epoch and marks the runtime inactive before other cleanup; render and command refreshes resolving after teardown may populate caches but must not mutate Scene state or publish query revision/invalidation. Backfill maintenance does not advance authoritative content revision, so sibling tickets from the same content may enrich disjoint Plants; the first sibling accepted for one Plant identity makes overlapping siblings stale, while preview and committed Canonical identities keep separate reservations until settlement chooses one. Retain accepted presentation metadata across history removal/restoration of the Plant. Validate both Plant identity and Canonical Name before applying an asynchronous backfill.
- Document replacement reserves a successor authority operation before canceling Scene Interaction or clearing fallible Target presentation. A live gesture's release hands authority directly to that successor without publishing an open slot; a cleanup failure before hydration removes the reservation, emits `CanvasDocumentReplacementNotAdmittedError`, and leaves the old Scene authoritative. Design Session must abandon that token and pending finalizer, while ordinary failures after `beginHydration()` retain them. Retained immediate/history recovery quarantines the replacement attempt, which must be retried. Once the Scene swap succeeds, invalidate old tickets immediately and keep replacement admitted through history clearing, projection, revision, render publication, and the caller's replacement finalizer. Replacement hydration alone owns the history clear and releases only after that idempotent finalizer; callers must not clear history or reset cross-authority baselines after release. The document surface requires an opaque logical replacement token. Design Session retains it across retries of one normalized input identity, including kind, path, and name; a retry resumes the original logical finalizer and never registers the retry call's fresh closure. That finalizer resets baselines and replaces Design identity as one batched stage, recording completion before reactive publication so a post-apply exception cannot make retry erase a later non-canvas edit. Equivalent file content carrying another token is a competing replacement: its triggering call may settle the retained operation, but is quarantined and cannot claim that operation's receipt. The document surface receipt reports whether the current caller's finalizer ran, allowing Design Session to acknowledge an already-finalized retained replacement without repeating state replacement or dirty-baseline reset. The authority owns an immutable snapshot of the accepted input and passes a fresh copy to each fallible projection attempt, so a retry remains stable when normalization produced a new object identity or caller/projection code later mutates an object it received.
- `CanvasDocumentSurface.captureForPersistence()` is the only public Scene save seam. It returns defensively owned composed content, exact-current observation, and an opaque, idempotent `acknowledgeSaved()` closure. Exact-current identity covers history/document/runtime identity plus the serialized presentation projection; keep those private and do not reintroduce separate public serialize and mark-saved calls.
- `CanvasAuthorityBusyError` is the app-facing contract for a temporarily unavailable exact Canvas capture. Design Session persistence may coordinate a deferred guard through that contract, but must not import concrete `SceneEditBusyError` or other Scene authority implementation types.
- Persistence capture during an open Scene Edit serializes the committed before-state while the live preview remains visible. Once history accepts a commit, reentrant capture serializes the committed after-state even if later publication phases are retrying. A retained undo/redo replay, hydration/replacement, or active presentation publication rejects capture as busy because Scene content and checkpoint identity may be between settlement phases.
- Acknowledgement revalidates document generation and runtime lifetime both before and after clean-state publication, because that callback may synchronously replace or dispose the runtime. Runtime disposal permanently closes persistence authority: existing closures become stale and a retained destroyed document surface cannot issue a fresh capture.
- Presentation backfills are non-dirty semantic enrichment. They may change serialized presentation metadata without creating a new history state identity, so they advance exact persistence-projection identity without dirtying history. Acknowledgement and undo cleanliness follow admitted semantic edits, not byte equality of derived cache data.
- Cross-authority workflows that write Design state from Scene data must consume a settled query such as `getSettledPlacedPlants()` and skip work while it returns `null`. Read-only visual projections may continue to use live-preview queries.
- Non-canvas document sections are not owned by `SceneStore`: consortiums, timeline, budget, `budget_currency`, description, and document extra.
- Historical wire optionality stops at Scene hydration. `ScenePersistedState` and renderer snapshots are total internal contracts, so runtime consumers must not repeat missing-array fallbacks such as `?? []`; tests should construct total snapshots through shared builders.
- The active Layer setting is app-owned Canvas Settings state, not Scene Session state. Layer visibility, opacity, and locks remain persisted Scene edits.
- Commands, tools, save/load, and document replacement mutate scene state, not renderer objects.
- Canvas-owned document fields serialize from the live scene, not stale document input copies.
- Full Design file composition is app-owned and crosses `CanvasRuntimeAppAdapter.document`. Runtime core serializes canvas-owned state and must not import `app/contracts/document`.
- Plant presentation state lives in `SceneStore.session`, not standalone canvas signals.
- Scene Layer visibility, opacity, and locks are scene edits. UI controllers must call the canvas command surface instead of writing `layerVisibility`, `layerOpacity`, or `layerLockState` directly.
- Canvas Layer Presentation (`app/canvas-layer-presentation/presentation.ts`) owns the visible Layer catalog and authority-correct row commands for scene Layers, basemap, contours, and hillshading. UI callers should consume that seam instead of hard-coding `base`, `contours`, or `hillshading` routing.
- Layer lock controls belong on scene Layer rows in the Layer Panel and must write through Canvas Layer Presentation. Layer-locked objects can show locked-Layer hover cues, but must not show object-level unlock affordances.
- Design Object lock state lives on persisted scene entities in `SceneStore`. Production code must read and mutate object locks through scene queries/edits, never through standalone mirror signals.
- Object Groups are flat and may span the Plants, Zones, and Annotations Layers. Grouping a selected Object Group with other editable Design Objects should merge the group's members into one flat Object Group, not create a nested group. When exactly one Object Group participates, preserve that group's identity, name, and selection. When multiple Object Groups participate, the topmost selected Object Group in scene order survives with its identity, name, and direct lock state; merge into that surviving Object Group and remove the other selected group records.
- Grouping should be idempotent over selection edge cases: expand selected Object Groups into concrete members, add selected concrete Design Objects, deduplicate by typed identity, and proceed only when at least two concrete members remain.
- Object Group Layer behavior and geometry are derived from member Design Objects. Object Groups should persist identity, optional name, lock state, and typed concrete member identity only; they should not persist standalone Layer, position, or rotation fields. Runtime code must not use standalone Object Group Layer or transform fields as authority for visibility, locking, hit testing, selection, mutation eligibility, bounds, pivots, or placement.
- Object Group membership must be typed so Placed Plant IDs, Zone names, and Annotation IDs cannot collide. Persist members as concrete Design Object references such as Plant, Zone, and Annotation; do not persist Object Group members inside Object Groups. Grouping existing groups should expand them into concrete members.
- Admitted Scene groups use typed members ([ADR 0007](../adr/0007-design-objects-and-personal-libraries.md)). Obsolete raw `member_ids` groups are refused at admission, never converted in runtime hydration ([ADR 0003](../adr/0003-no-backward-compatibility.md)).
- Cross-Layer Object Groups are editable only when all existing member Design Objects are on visible, unlocked Layers. If any member Layer is hidden, the group should not be selected as a group from canvas hit testing; visible members of that group remain structurally blocked from individual selection so users cannot partially edit a group with hidden members. If any member Layer is locked, mutation commands for the group must be unavailable and the group should be treated as a structural blocker rather than an object-level Unlock target.
- Ungrouping an Object Group should select the resolved concrete former members that are visible and editable after the group record is removed. Missing stale members are ignored.
- A group is effectively locked for mutating canvas interactions when the group itself is locked, any existing member Design Object is locked, or any existing member Design Object is on a locked Layer. Missing member IDs do not lock a group.
- Directly locked Design Objects stay hover-discoverable and can become selected locked targets so the Selection Action Toolbar can offer Unlock. They must not become editable targets until unlocked; other mutation buttons should be visible but disabled in the locked-selection toolbar state. Locked-Layer objects, hidden objects, grouped members, missing targets, and Object Groups blocked only by locked members remain structural blockers rather than selected locked targets. Do not reintroduce implicit unlock-all behavior through `unlockSelected()` or shortcuts.
- Movement, color, and other mutating commands must derive write targets from the typed editable-selection model or explicit Layer/lock filters. Broad Species scopes may include blocked targets for read-only affordances and must not be used directly for Scene mutations. Lock reads and writes accept typed targets; do not add raw-ID lock helpers.
- Guide creation is a scene edit owned by the runtime. The `guides` signal is a chrome projection, not document authority.
- Runtime chrome rendering and interaction snapping read guides from `SceneStore.persisted.guides`; do not read the `guides` signal in production runtime behavior.
- Canvas signals such as selected object IDs, layer state, and guides are UI mirrors, not runtime authority.
- Canvas Query Surface revision values are the app-facing freshness seam for scene entities and localized Plant names. Viewport callers subscribe to the atomic `CanvasQuerySurface.viewport` snapshot instead; do not recreate `runtime-mirror-state.ts`, viewport mirrors, or mirror revision signals.
- Canvas Map Surface reads the confirmed Location projection and `north_bearing_deg` from the document-owned spatial frame through the Location Workbench presentation seam, not `scene-metadata-state` or direct document-session imports. Provisional frames remain persisted but do not activate geographic map sources.
- `canvas/runtime/scene-physical-extent.ts` owns the pure radial physical extent of the Scene from design origin `(0, 0)`. It includes Placed Plant centers, effective Zone geometry, Annotation anchors, and both Measurement Guide endpoints; it deliberately excludes screen-readable Plant and Annotation Visual Footprints. It delegates every Zone shape through `zone-geometry.ts#getZoneRadialExtentMeters`; keep line, polygon, rotated rectangle, and rotated ellipse dispatch behind that one interface, including the true Elliptical Zone radial extremum rather than sampled perimeter points or an axis-aligned bounds corner.
- Basemap, contour, and hillshade display settings remain app settings projections; do not route those map-surface settings through Scene Edit unless the document schema intentionally makes them canvas-owned.
- Shared runtime settings reads, writes, and subscriptions for locale, theme invalidation, grid/rulers/snap, Plant Spacing interval, and layer projections cross `CanvasRuntimeAppAdapter.settings`. Runtime core must not import `app/settings/*` or `app/canvas-settings/*` for those concerns.
- Runtime-owned user-visible strings resolve through `CanvasRuntimeAppAdapter.translate`. Desktop and browser adapters inject the application `t()` authority; detached and test adapters must supply an explicit deterministic translator. Runtime core must not import `i18n/*`, duplicate locale resources, or read locale merely to choose translated chrome.
- No circular imports between scene store/runtime and document store. Pass document readers or values through seams when needed.

## History And Dirty State

- `SceneHistory` dirty state uses unique state identities. A checkpoint names the exact current identity: acknowledging it can leave later commands dirty, undo to it becomes clean, and a divergent branch at the same stack depth remains dirty.
- `SceneHistory` is a private authority collaborator. Command callers consume only `SceneHistoryCommands`; persistence consumes an opaque closure issued by `ScenePersistenceAuthority`. Neither surface may execute raw history operations or obtain a history runtime that can write `SceneStore`.
- `SceneHistory` reports canvas clean-state through an injected clean-state callback from the `CanvasRuntimeAppAdapter`. Production wiring lives in `app/canvas-runtime/app-adapter.ts`; runtime core must not import `app/document-session/store`.
- A production `SceneHistory` subscribes to shared branch announcements for its runtime lifetime and unregisters during document-surface teardown. This subscription coordinates redo availability only; it does not transfer Scene state or replay authority into Design Session.
- Clearing history advances its checkpoint generation and makes older checkpoints stale. Runtime disposal separately invalidates captures so acknowledgements cannot publish into a later runtime lifetime.
- Any history truncation or branch behavior must preserve unique saved-state identity in all write paths; never derive cleanliness from past-stack length. If the saved identity remains reachable at the truncation boundary, undoing to it must still become clean.
- Selection, hover, presentation-only target highlights, labels, and viewport-only work must not create document history entries unless explicitly designed.
- Auto-fit on attached document open is expected; attached Design Session transitions call `zoomToFit()` after hydration. Detached transitions must not call canvas-only document surface methods.
