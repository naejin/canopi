# Canvas interaction and tool lifecycle

Part of the [Canvas runtime guide](canvas-runtime.md). Read this guide for interaction ownership. For persistence across runtime lifetimes, use [Document lifecycle](document-lifecycle.md).

## Interaction Ownership

- Unmodified vertical wheel input zooms around the pointer. Shift + wheel pans both axes; Ctrl/Cmd + wheel and wheel-based trackpad pinch retain pointer-anchored zoom, including when Shift is held. Apply this explicit modifier policy to both mouse and trackpad events without device heuristics. Space-drag and middle-button pan remain available. The interaction owner normalizes pixel/line/page deltas (16 CSS px per line; viewport dimensions per page), applies the calibrated exponential zoom response, and publishes only effective viewport changes. Empty/nonfinite deltas and movement beyond scale limits do not render. Native editors and owned controls retain wheel input, and teardown removes the wheel listener.
- In overview, primary drag pans regardless of the armed tool. Entering overview cancels active drafts/editors, clears transient selection affordances and quarantines their late pointer-up; spatial creation, mutation, paste/drop and delete/group/order/lock commands are unavailable. Navigation, Return, copy/select reads, history, layer visibility and panel-authorized non-spatial operations remain available. Tool choice may stay armed for site re-entry.

- The factory-created `SceneInteractionSession` in `canvas/runtime/scene-interaction.ts` owns live listener lifetime, pointer capture, generic drag routing, active-tool transitions, cancellation, refresh ordering, pending host focus, and teardown. Tool adapters own only tool-specific draft and geometry state.
- Hit testing and selection geometry must stay scene-side.
- Off-canvas drag continuation, multi-drag, and additive selection behavior are part of the runtime contract.
- Species Selection is a Select-tool canvas selection gesture: double-clicking a visible editable top-level Placed Plant selects all visible editable top-level Placed Plants with the same Canonical Name across the design, excluding grouped members, locked Design Objects, hidden Layers, and locked Layers. Shift+double-click applies the same Species set additively/toggling against the current selection. The Selection Action Toolbar uses `CanvasDesignObjectSelectionModel.sameSpeciesReferenceCanonicalName` to expose Select Same Species and dispatches the non-dirty `selectSameSpecies()` command. It must not mutate Design data, Target Presentation, dirty state, or document history.
- Plant hit testing must use the same shared presentation context as renderers and fit/bounds logic.
- Interaction selection writes go through the runtime-owned selection seam.
- Editable hit testing should continue to ignore locked Layers, but hover feedback may use visible-only hit testing so locked Layers and locked Design Objects can explain why an object is blocked.
- Document-level keyboard handlers must guard with `isEditableTarget(event.target)` so Delete/Backspace/etc. do not fire while typing.

### Scene Interaction Tool Modules

- Tool modules are internal adapters behind `canvas/runtime/interaction/tool-modules.ts`; they do not change the public `SceneCanvasRuntime`, `CanvasCommandSurface`, `CanvasQuerySurface`, or `CanvasDocumentSurface` interfaces.
- The Scene Interaction Session exposes only tool synchronization, measurement and translation refresh, transient-history operations, and idempotent disposal to `SceneCanvasRuntime`. Do not reintroduce public attach/detach, raw-handler injection, pointer-state getters/setters, or cleanup callback APIs.
- The Session installs every container/window listener, caches pointer-down bounds for the captured gesture, holds the single pointer/Space/generic-drag session, and encodes fixed event priority explicitly. `pointercancel` accepts only the matching pointer ID; matching cancellation and window blur abort active edits without history, clear hover, release Space, restore the active-tool cursor, and leave the next gesture usable. If cancellation throws before an active transaction closes, retain ownership and quarantine later pointer, drop, context-menu, wheel, and keyboard mutation routes while retrying cancellation; never let a new gesture or command overwrite retained work. Drag-over eligibility and preview are observational: use `SettledSceneReader` so pointer movement cannot resume retained maintenance; actual drops remain whole admitted commands. A rejected or throwing settled drag-over read must reset `dropEffect`, remove Plant/Saved Object preview feedback, and quarantine downstream drag-over handlers. Pointer-down and keydown admission use capture-phase listeners so pending cancellation runs before overlay buttons and global command dispatch. Pointer-move/up/cancel continuation also runs in capture phase so an owned overlay cannot strand a live gesture by stopping event propagation; when no gesture is live, those same capture handlers must return owned overlay targets to their target-phase button/HUD handlers without clearing overlay state. Preserve a valid passive Polygon draft when interruption cancels Space or middle-button panning.
- After pending cancellation gets first refusal, keydown targets inside runtime menus, toolbars, dialogs, links, buttons, or editable controls must return to normal DOM activation before the active tool sees the key. Runtime tool commands must complete the authoritative Session transition before publishing the active-tool UI mirror. Failed cancellation must leave both on the previous tool; activation or post-switch refresh failure must roll back the adapter, Session tool, settled cursor, and selection presentation before returning the failure.
- Test Scene Interaction through the user-equivalent event harness in `desktop/web/src/__tests__/support/scene-interaction-events.ts`. Broad tests should dispatch pointer, cancellation, keyboard, focus, wheel, context-menu, and drag/drop events instead of reaching into Session handlers or state.
- Shared panning, band selection, top-level Design Object dragging, snap-adjusted drag deltas, and shared gesture cleanup live in `canvas/runtime/interaction/shared-gestures.ts` behind the Session. Aborting a live Design Object drag must restore the Scene transaction and invalidate the restored scene. Band selection may keep a transient preview without reserving authority, but pointer-up completion is a whole settled command event; if another Scene Edit owns authority, quarantine that pointer-up, cancel the band, and do not write selection into the other edit's snapshot.
- Tool construction and adapter identity belong in `tool-modules.ts`; its registry must not mirror every optional adapter hook. The Session invokes the active `SceneToolAdapter` directly, owns transition/refresh/disposal order, and deduplicates shared adapter cleanup hooks.
- Session disposal detaches listeners first, cancels pending focus and active Scene Edits, then attempts every owned overlay/tool cleanup even if one fails. Runtime-owned resources use `canvas/runtime/cleanup.ts` when teardown must continue across independent owners and aggregate failures. Disposal is terminal and idempotent, and listener-installation failure must roll back listeners plus already-constructed resources before rethrowing. Collaborator factories that append DOM before returning must also remove partially acquired roots when later construction or eager refresh fails. `SceneCanvasRuntime.init()` is failure-atomic: Session-construction or initial-render failure destroys the partial Session, chrome/effects, and renderer ownership before rejecting.
- Tool modules own tool-specific state machines, including setup, per-event handling, refresh-after-viewport-change behavior, cancellation, and teardown for their own transient state.
- Shared tool context may expose only runtime-owned seams and stable projections: `SceneStateReader`, `WorkspaceCameraFrameReader` and the navigation role where required, Scene Edit transactions, selection setters/readers, hit testing, snapping/grid/guide reads, render invalidation, localized Species names, the injected runtime translator, plant presentation context, settings commands or projections, and DOM overlay containers. Never expose the concrete `SceneStore` to a tool.
- Tool modules may create DOM overlays for tool-owned chrome, but the module that creates an overlay owns its cleanup. Session-owned overlays stay Session-owned until a later bead deliberately moves them behind a tool module.
- Creation tools must guard the target scene Layer at the mutation boundary, not only through visible UI state. Plant Stamp and drop-to-canvas use the Plants Layer, Zone drawing uses the Zones Layer, and text Annotation creation uses the Annotations Layer; hidden or locked target Layers must not create scene edits, dirty state, stale previews, or new entities.
- Selection transform affordances such as the Rotation Handle, live rotation readout, and Selection Action Toolbar should be runtime-owned DOM overlays coordinated by the Scene Interaction Session/shared selection behavior. They must not be renderer-owned projections or outer Preact chrome that reaches into runtime internals.
- `canvas/runtime/interaction/control-point-overlay.ts` owns the shared Control Point Overlay DOM, drag threshold, Scene Edit transaction, final pointer update, cancellation retry, presentation cleanup, construction rollback, and disposal lifecycle. Scene Interaction composes Control Point controllers as one collection. Zone and Measurement Guide adapters retain eligibility, geometry derivation and constraints, draft writes, equality, labels, and optional live measurement presentation; do not copy the lifecycle back into either adapter or widen this seam to Rotation Handle semantics.
- The Selection Action Toolbar and Rotation Handle are Select-tool-only selection affordances. Hide them for Annotation Text, Zone drawing, Plant Stamp, Object Stamp, Plant Spacing, Hand, inline Annotation editing, Canvas Context Menu interaction, active Design Object drags, active rotation drags, active Zone Control Point drags, and future non-select tool interactions.
- Single-selection Rotation Handle drags are Scene Edit transactions owned by the runtime overlay. They must update rotation live, commit one history entry only past the no-op angle threshold, and abort cleanly on Escape, dispose, tool transition, or tiny/no-op pointer-up.
- Multi-selection and Object Group Rotation Handle drags use one pivot from combined visual bounds. Placed Plants rotate by moving positions without adding visible plant orientation; Rectangular/Elliptical Zones move their centers and increment orientation; Linear/Polygonal Zones rotate points; Object Groups transform member geometry only; the group has no persisted position or rotation, and its pivot is derived from combined visual bounds.
- The Selection Action Toolbar reads `CanvasQuerySurface.getDesignObjectSelection()` through the interaction deps, dispatches mutations through a narrow `CanvasSceneEditCommandSurface` role, and must not steal focus when it appears. Icon-only buttons may expose custom tooltips and focused keyboard activation, but hover/highlight alone must not make keyboard activation implicit. Action tooltips open above the toolbar, and the toolbar stacking layer must stay above the Rotation Handle so hover labels remain readable.
- Selection Action Toolbar placement must not block direct manipulation affordances such as Zone Control Points. Prefer non-overlapping placement; if no clear placement exists, hide or offset the toolbar instead of requiring a user-managed close button. Clear all toolbar button tooltip state whenever the toolbar hides, contents change, selection changes, active tool changes, disposal runs, or a transient interaction starts.
- The Selection Action Toolbar should show Group for any editable top-level multi-selection whose flattened typed concrete member set has at least two members and whose member Layers are all visible and unlocked, including mixed Placed Plant, Zone, Annotation, and Object Group selections. It should show Ungroup for selected editable Object Groups.
- Group/Ungroup shortcuts, menus, and toolbar actions must dispatch through the same Scene Edit command behavior. The command may no-op for ineligible selections, but toolbar availability and command eligibility should be derived from the same flattened typed member rules.
- Select-tool Design Object drags hide the Selection Action Toolbar and Rotation Handle from drag start until the drag ends or is canceled. Restore them only after the scene/selection refresh so their placement reflects the final geometry. During active drags, clear passive hover presentation such as Hover Tooltip, hovered entity projection, and locked-object affordance; do not force Hover Tooltip to reappear on pointer-up.
- Pointer-up, interruption, and Control Point commit/cancel paths must restore drag presentation and run their final measurement refresh even when rendering or another cleanup reports an error. Keep each active drag transaction reachable until commit or abort finishes. A commit failure before history accepts the transaction may cancel back to its captured snapshot; a later publication failure must retry the already-recorded committed outcome.
- Runtime-owned overlays such as the Selection Action Toolbar, Rotation Handle, locked-object affordance, and tool HUDs may suppress passive hover/preview pointermoves, but active pointer gestures must receive movement before overlay ignore checks so drags, pans, and rotations do not freeze while crossing overlays.
- Locale subscription changes route through one Scene Interaction Session translation refresh. Mounted Context Menu, Selection Action Toolbar, Rotation Handle, locked-object affordance, and Plant Spacing HUD controllers update their existing text and ARIA nodes in place; translation refresh must not recreate overlays, change visibility/tool phase, reset Plant Spacing interval/count/preview state, or disturb focus and input selection.
- Selection Action Toolbar command availability should be derived from the selection read model. Keep mutation and dirty/undo behavior behind the command surface and Scene Edit transactions rather than duplicating it in overlay code.
- Scene Interaction Session owns canvas-scoped browser-default suppression such as `contextmenu`; handlers should preserve native behavior for editable targets and non-canvas panels.
- Pointer, context-menu, and drop events that encounter a retryable pending authority settlement may finish that settlement, but must quarantine the triggering event whether recovery returns busy or throws. Never continue hit testing, selection, dragging, menu presentation, or placement from an event whose initial Scene assumptions were made while unsettled.
- The Canvas Context Menu is a runtime-owned canvas overlay coordinated by the Scene Interaction Session. It dispatches Copy, Paste, and Delete through canvas scene-edit command surfaces, keeps unavailable commands visible but disabled, and must place itself dynamically inside the visible canvas so app chrome or viewport edges do not hide it. Hiding or replacing a document clears the menu's captured world point and focus so a stale button cannot act on the next Scene.
- Canvas Context Menu target selection follows design-tool behavior: right-clicking an unselected editable top-level Design Object selects only that object; right-clicking a Design Object already inside the current selection preserves the current selection; right-clicking empty canvas preserves selection and uses the clicked canvas point for context paste. Right-clicking a directly locked Design Object may select it as a locked target, but Copy and Delete remain disabled because locked objects are not editable mutation sources. Right-clicking a visible but structurally blocked Design Object, such as a locked-Layer object or Object Group blocked by a locked member, must not leave an unrelated editable selection active for Copy/Delete; those commands stay disabled for that menu context. Resolve the topmost visible hit before falling back to editable-only hit testing so a blocked object over an editable object does not retarget the menu to the object behind it. Copy and Delete availability requires an editable selection with no locked or blocked targets; mixed editable plus locked/blocked selections keep those commands visible but disabled.
- Do not open or retarget the Canvas Context Menu while a direct-manipulation Scene Edit is live. Suppress that context-menu event without canceling the active edit so its existing pointer continuation can still commit or abort normally.
- `canvas/runtime/scene-runtime/arrangement-placement.ts` is the shared authority for placing copied Scene arrangements. Clipboard Paste/Paste At/Duplicate, Object Stamp, and Saved Object Stamp must adapt their source into a `SceneArrangementTemplate` and delegate fresh identity allocation, cross-kind identity and Zone-name collision handling, ellipse translation, typed Object Group remapping, atomic insertion, and canonical top-level selection to that transaction-owning seam.
- Arrangement source policy stays with its caller: clipboard capture and pin behavior, Object Stamp sampling/revalidation/repeated preview, and Saved Object Stamp decoding/Layer eligibility/one-shot ghost lifecycle do not belong in the placement seam. Keep explicit source identities in adapters, especially where a Saved Object Stamp Zone payload ID differs from its user-visible Zone name.
- Normal Paste and Duplicate use the internal canvas clipboard and place copies one meter to the right of the copied Design Object selection; repeated normal Paste or Duplicate advances one additional meter to the right each time. Context Paste from the Canvas Context Menu recomputes the copied payload's combined visual-bounds center with the current viewport and presentation context at paste time, then translates the copied Design Objects so that center lands on the clicked canvas point, preserving relative geometry and group membership.
- Saved Object Stamp placement should follow Paste/Object Stamp transaction semantics: one drop or click placement is one Scene Edit history entry, undo removes all objects created by that placement, and the final selection contains the newly placed top-level Design Objects. Placement does not create a new Object Group just because the stamp contains multiple objects, but Object Groups captured inside the stamp remain Object Groups with remapped members.
- Saved Object Stamp capture is a whole settled Scene command because it reads selection and persists an external library entry. Favorites UI and context actions dispatch `saveSelectionAsObjectStamp()` through the command surface; they must not call the workbench capture method directly. Native drag feedback and drop placement also cross command admission, and a rejected busy drop must preserve its source for retry.
- Saved Object Stamp placement anchors the stamp's combined visual-bounds center at the pointer/drop point and preserves relative geometry, size, spacing, orientation, colors, symbols, annotation text, Zone geometry, and captured group names. Do not auto-scale, rotate to cursor, substitute Species, or depend on Species Catalog availability for placement.
- Saved Object Stamp placement is all-or-nothing across target Layers. If any object type in the stamp requires a hidden or locked target Layer, block placement with feedback instead of creating a partial arrangement. Placed copies are unlocked even when directly locked source objects were captured into the saved stamp.
- Saved Object Stamp save eligibility may include directly locked selected Design Objects, but must still reject structural blockers such as hidden Layers, locked Layers, missing targets, and grouped members selected outside their Object Group. Grouped members should be saved through their selected Object Group instead.
- Saved Object Stamp payloads should preserve visible arrangement data only. Strip lock state, plant notes, planted dates, plant quantities, Zone notes, and other non-visual planning data unless a field is required to avoid invalid Design Objects or broken group membership.
- Saved Object Stamp drag/drop and armed placement should show full ghost copies of the arranged plants, zones, annotations, and captured groups in their real relative positions, using translucent non-interactive styling. Exact placement ghosts belong to the canvas runtime; framed recognition thumbnails for library inspection belong to the Favorites panel. If target Layers block placement, do not show the arrangement ghost; surface blocked feedback instead. The placement preview should update with snapping and disappear on placement, cancellation, tool switch, document replacement, or runtime disposal.
- Scene edits from tools must go through `SceneEditCoordinator`; modules must not mutate persisted scene arrays outside the Settled Scene Authority except for explicitly transient draft state owned by the runtime. Non-tool commands that read Scene state before writing must also cross the authority's caller-shaped settled-command admission for the whole operation.
- Drag-to-create Line, Rectangle, Ellipse, and Measurement Guide tools own a long-lived Scene Edit from accepted pointer-down through pointer-up commit or cancellation. This prevents an unrelated immediate command from consuming pointer-up recovery. Keep the draft transaction reachable until commit/abort settles and report it through the tool adapter's active-edit query. Use `onCommitted` for fallible, idempotent overlay cleanup, but clear the retained draft handle only after `commit()` returns: the authority still performs a fallible post-continuation backfill drain before release, and a quarantined later event must be able to resume it through the same handle.
- Tool modules must treat `setTool()` changes, `dispose()`, document replacement, Escape cancellation, source invalidation, and viewport refresh as lifecycle events that leave no stale overlays, listeners, selections, previews, or pointer capture behind.
- Do not install module-level `effect()` or global listeners from a tool module unless that module also owns an explicit disposer and `import.meta.hot.dispose()` cleanup. Prefer Session-dispatched events for canvas tool input.
- Current Scene Edit tool adapters include Annotation Text, Zone drawing, Object Stamp, Plant Stamp, and Plant Spacing. Do not reintroduce tool-specific fields, source state, preview state, or direct tool branches into the Scene Interaction Session; route through a `SceneToolAdapter` and keep the state machine in the tool module.
- `canvas/plant-stamp-source.ts` owns Plant Stamp Source selection plus drag data parsing/serialization. Plant Stamp tool modules consume that seam and clear the selected source on adapter deactivation/disposal; Species Catalog UI modules call it instead of writing source state or hand-assembling drag payloads.
- Guard Scene Edit ownership with source boundary tests in `scene-interaction-tool-boundary.test.ts`, focused tool-module tests such as `plant-spacing-tool.test.ts`, and user-equivalent Session lifecycle tests in `scene-interaction.test.ts`. Add tests before moving another tool concern across the Session/adapter boundary.
