# MapLibre Integration

Use this guide when changing MapLibre surfaces, basemap rendering, terrain layers, map/canvas projection, or map overlay behavior.

## Ownership

- MapLibre is a derived visualization layer, not a document authority.
- Map layers render scene/document state; they do not own or mutate it.
- The map is the canvas ([ADR 0001](../adr/0001-geolocated-map-canvas.md)). Map presentation never depends on a Design location or placement state; camera movement, fit and place search never move objects.
- `maplibre/host.ts` owns shared MapLibre resource lifetime for migrated map-backed surfaces: lazy loading, map creation, resize observation, keyed rebuild teardown, preserved view state, initialization failure callbacks, and final removal. The host must not import app-owned Design, Location, Target Presentation, terrain, or canvas authority.
- The host snapshots a constructor call's direct container children and class names. Constructor failure and every later map-removal path roll back only that synchronous identity/class delta; do not select broad MapLibre CSS classes or remove pre-existing or later app-owned DOM.
- `maplibre/surface-adapter.ts` is the typed adapter seam above the MapLibre Host. Production map-backed surfaces should request map lifetime through the MapLibre Surface Adapter so typed map access, map-lifetime cleanup callbacks, and event listener cleanup stay out of app/components code.
- Keep direct `maplibre-gl` imports, Map/Marker/Bounds construction, basemap style construction, and control construction in low-level modules under `desktop/web/src/maplibre/` or in tests.
- In-canvas MapLibre remains isolated behind the Canvas Map Surface adapter and the MapLibre Host. Do not scatter MapLibre ownership across canvas runtime or renderers.
- `WorkspaceMapControls` performs the browser WebGL2 preflight before attaching the MapLibre surface. An unavailable context publishes the map surface error state and rejects map admission before any MapLibre map or browser listener exists; the workspace resolves `map-unavailable` with no renderer mounted.
- Place search is a pin icon button under the inspection lens button. It accepts a place name (through the shared geocoding provider registry, Enter only, at least 1.1 s between requests, OSM attribution) or coordinates (parsed locally). Confirm moves only the camera (`viewport.showPlace`). The registry (`app/geocoding/registry.ts`) is shared; the edition transport is the `#geocoding-transport` alias (`transport.desktop.ts` routes Nominatim through the native `geocode_address` command, `transport.browser.ts` uses `fetch`). `app/geocoding/place-search.ts` owns pacing and coordinate parsing; `components/canvas/PlaceSearch.tsx` is the UI, opened by the pin, `Ctrl+F` (`view.searchPlace`) or the empty-Design "Search your site" prompt.
- Web scope follows [ADR 0005](../adr/0005-web-edition-scope.md): the same basemap and satellite providers and the shared geocoding registry through browser `fetch`. **Excluded from Web**: Tauri or native imports, local raster rendering/processing, a backend or tile proxy, bulk download, an offline imagery archive, and any service worker. `desktop/web/scripts/check-web-build-boundaries.mjs` enforces the exclusions and must not be weakened.
- `maplibre/basemap-tile-auth.ts` is the **credential boundary** for official provider tiles. A published descriptor carries the credential-free endpoint template `https://tile.googleapis.com/v1/2dtiles/{z}/{x}/{y}?session={session}`; the map is created with a `transformRequest` seam closing over that map's own `BasemapTileAuth`, and the transport substitutes the live session and appends the key **for that fixed endpoint only** — any other URL, caller-supplied or third-party, passes through untouched. The credential never enters published state, a Design, an export, a report or a log. A map created without a transport therefore cannot serve the official path at all: `maplibre/basemap-contribution.ts` withdraws an official contribution whose `{session}` cannot be resolved instead of installing a source that would fail every request. The provider publishes into the auth object while it is live and clears it on disposal, so credentials are scoped to the map lifetime that installed them.
- **Map layer store.** `app/map-layers/state.ts` owns Basemap (OpenFreeMap style, visibility, opacity), Satellite (provider, visibility, opacity), Contours and Hillshade; `app/map-layers/actions.ts` mutates them through the settings projection (toggles persist immediately, sliders queued). Map layers are not undoable and never enter a Design. `mapBackgroundOf()` decides the background band: Satellite on hides the Basemap without changing the Basemap's own toggle. `app/map-layers/bands.ts` orders Canopi layers into bands (background, LiDAR, terrain references, shared scene, interaction overlays).
- **Background band.** `maplibre/map-background.ts` (`mountMapBackground`) is the one owner of a map's Basemap, Satellite and attribution control; both the workspace map controls and the templates world map mount it, so no surface binds a basemap itself. `maplibre/openfreemap-basemap.ts` installs the OpenFreeMap vector style (Liberty, Positron, Bright, Dark; presets copied from GeoLibre, see `THIRD_PARTY_NOTICES.md`) as `ofm-` sources and `ofm:` layers plus `setGlyphs`/`setSprite`, without `setStyle()`. Row opacity scales every style layer's paint opacity (zoom curves keep their top-level interpolate/step shape); labels use `name:<locale>` falling back to `name`. OpenFreeMap credit comes from its TileJSON; the Google viewport copyright is custom attribution on the same single control.
- **Satellite provider.** `maplibre/satellite-provider.ts` resolves `eox` (EOX Sentinel-2 cloudless 2017, CC BY 4.0, keyless, maxzoom 17) or `google` (official Map Tiles API session; unavailable without a device key, never a keyless path). `satellite-provider-session.ts` owns Google session acquisition, viewport metadata, renewal and fencing; `satellite-contribution.ts` reconciles the one raster source/layer; `satellite-bind.ts` wires them to a map once its style can accept sources. OSM raster tiles, MapTiler and keyless Google are gone.
- [ADR 0008](../adr/0008-canvas-pdf-export.md) defers all map backgrounds from Canvas PDF in v2.0. The PDF export path must not mount or capture a map surface or fetch map assets. When PDF map work resumes, preserve required attribution and validate the source for print coverage, resolution, and provider terms; interactive loading alone does not establish print suitability.
- The Design Template world map uses the MapLibre Surface Adapter for map lifetime and keeps template marker creation, selection classes, fit-to-bounds, and selected-template fly-to behavior in `components/world-map/WorldMapSurface.tsx` with low-level constructors isolated under `maplibre/world-map.ts`.
- `app/canvas-map-surface/workspace-activation-snapshot.ts` reads the nullable Design session identity, the initial map centre (session plane origin) and the background presentation (`readWorkspaceBackgroundPresentation`: map layer store + locale). Edition contribution adapters read the supplied query surface for live LiDAR, terrain, frame, Target, bounds, diagnostics, and readiness inputs; they do not construct a second map lifecycle or read Desktop capabilities from Web.
- `maplibre/shared-scene-layer.ts` is the qualified production custom-layer adapter. MapLibre supplies its canvas, WebGL2 context, resize, and render callback; the adapter owns only Pixi graphics resources and the retained botanical presentation. Scene updates and camera-only invalidations call `triggerRepaint()`, and drawing occurs only inside MapLibre's custom-layer callback with `clear: false`. Every admitted callback still submits the retained Pixi stage so MapLibre compositing remains complete, while an unchanged camera and unchanged size skip redundant presentation synchronization. A pending Scene snapshot or resize always synchronizes presentation before submission. `maplibre/scene-camera-transform.ts` derives the local-metre viewport from live MapLibre projection and rejects pitch or excessive affine residual.
- `maplibre/shared-scene-renderer.ts` composes the workspace map custom layer with the renderer-neutral bridge in `canvas/runtime/renderers/maplibre-scene.ts`. Custom-layer failures reach the layer's `onFailure` observer; the workspace coordinator then unmounts the renderer. There is no renderer failover.
- **Sources are applied only once the map can accept them.** MapLibre loads even an inline style asynchronously and `addSource` throws before that, so the background band waits for `mapStyleReadiness(map, lifetime)` and then applies the latest presentation, not the first. Settled `moveend` refreshes Google viewport metadata only (never a new session); renewal publishes `loading` while it runs so a dead token is never used. Providers and credentials are disposed with their map.
- `maplibre/workspace-map.ts` creates the non-interactive shared-workspace map shell from a source-free inline style. It must request an antialiased canvas context when constructing MapLibre: Pixi receives that existing context later, so its renderer option cannot enable multisampling after creation. `app/canvas-map-surface/workspace-map-controls.ts` adapts that shell to transactional admission through one MapLibre Surface Adapter: each `createMap(signal, snapshot, sessionIdentity)` attempt retains immutable session construction facts and its own latest immutable `WorkspaceBasemapPresentation`. `updateBasemapPresentation()` is scoped to the current attempt: it normalizes opacity to `[0, 1]`, retains updates during acquisition, and is inert after release. It changes opacity with `setPaintProperty()` only; hide removes the raster layer before its source; show/style changes replace only that contribution. Hidden presentation never adds remote source work. The raster contribution is placed immediately above the local background and before all later layers, preserving unrelated layer identity and order. Initial `style.load` admits the map only. One attempt-scoped reconciliation drain serializes later same-map style reload and presentation work: it applies the latest retained presentation, invokes one map-lifetime scene restorer only for reload work, then restores semantic order; reentrant signals are coalesced and replayed, while a failed mutation fences every later drain. The operation never calls `setStyle()`, recreates the map/camera/custom scene layer/runtime, or rereads Design/settings state. It obtains WebGL2 from the public map canvas, retains context loss or generic map failure until the coordinator installs its watcher, and delegates every final removal to the Surface Adapter. Hosted basemap and recognized contribution source errors are passive; one mutation/restoration failure flows through the existing watcher and generic map failures fail the shared backend. This adapter is the production map path in both editions.
- The shared workspace shell stays `interactive: false`. Pointer pan and wheel reach the single Scene Interaction owner, whose navigation commands target `MapLibreWorkspaceCameraOwner`; MapLibre must not install an independent drag, wheel, pinch, or pointer-capture owner. Tool/object gestures therefore mutate Scene/history only, while navigation changes the map-backed frame only. Detach returns the owner to detached session-plane navigation; nothing draws without a map.
- The workspace map constructor uses `minZoom: 0`, `maxZoom: 27`, `bearing: 0` and `renderWorldCopies: false`, centred on the snapshot's `initialCenter` (the session plane origin). Hidden basemap presentation must not add remote sources. Geographic edges constrain camera navigation instead of wrapping geometry into another world.
- `app/canvas-map-surface/workspace-activation.ts` owns transactional shared-workspace admission. `activate(snapshot)` binds one opaque Design session identity, the map's initial centre, an owned latest basemap presentation, and optional maximum world extent to a generation. `updateBasemapPresentation()` buffers the latest value for the newest acquiring generation and forwards only after its controls attempt exists; it is inert for a superseded/disconnected generation, a terminally unavailable map, or as soon as terminal teardown is requested, and cannot recreate a map, camera, custom layer, or Scene runtime. Map creation, WebGL2 acquisition, canonical custom-layer initialization and attachment, and accepted camera attachment must all complete before the first `SceneCanvasRuntime.init()` mounts `maplibre-pixi`; remote tile readiness is not an admission condition. `requestGenerationDisconnect()` is intentionally non-async: it publishes one retained generation settlement before aborting acquisition, fences callbacks, detaches camera ownership, and invokes layer disposal synchronously. The retained result exhaustively joins resource cleanup and any already-admitted map failure handling; map removal waits for layer disposal. Repeated requests share that settlement; activation and terminal teardown join it, while one rejected settlement blocks one successor admission before a later request may recover. Resource callbacks may synchronously request another coordinator operation, and a void callback receives its real retained settlement. A child setup, disposal, initialization, or renderer-unmount Promise must never adopt or await an owner operation that joins that child; direct returns are rejected as ownership violations, and wrapped or delayed back-edges are invalid by contract because JavaScript Promises cannot expose their dependency graph. Replacing A with B first removes A's restorer and failure watchers, detaches its camera, disposes its layer while the context is valid, and releases its map. It then creates B while retaining the initialized Scene runtime and renderer bridge, whose disconnected snapshot replay seeds the new layer. Equal map values with a new session identity still form a new generation. After a same-context style reload, the coordinator idempotently ensures that generation's initialized canonical layer is attached after the controls restore its bound basemap. Before-first-init failure cleans the attempted generation and resolves `map-unavailable` without initializing the runtime. Failure after runtime initialization cleans that generation, unmounts the runtime renderer once, and permanently fences map restart for that coordinator. Public teardown is memoized, joins generation cleanup and pending initialization, reports their errors to every caller, then alone destroys the runtime once. The newest activation request wins; abort and generation fences reject stale map, initialization, style, camera, and failure callbacks.
- `app/canvas-map-surface/workspace-runtime-composition.ts` composes the single shared camera, the one MapLibre renderer, coordinator, and reconciler. `desktop-workspace-runtime.ts` and `web/browser-workspace-runtime.ts` mount it in the respective editions through `WorkspaceRuntimeMountOptions`; the final runtime container is passed straight to the composition. These factories pass retained live basemap and immutable contribution snapshots to the coordinator; updates do not create or replace map/scene resources.
- `app/canvas-map-surface/workspace-map-contributions.ts` owns the controls attempt's session-bound presentation: incremental LiDAR, terrain generation fences, panel Target overlays, semantic ordering, readiness/terrain state, view bounds and diagnostics. It reconstructs from the latest captured snapshot after `style.load`, uses the same map and camera, and fences synchronous reentrant mutations and stale async terrain completion. Failed LiDAR IDs stay omitted until their source shape changes or the style reloads; terrain load/source/rebuild errors leave editing ready only after their partial contributions are removed successfully. Failed LiDAR removal (including obsolete layers) or failed terrain rollback enters the one-shot hard map failure path with the cleanup error; it must never claim passive omission while partial resources remain. Overlay sync and semantic-order failures are terminal: the manager disposes once and reports through the controls failure watcher; ordering after an async terrain rebuild stays outside passive terrain error handling. A fatal contribution failure during initial restoration rejects acquisition before watcher installation. Generation disconnect clears contribution inputs synchronously; release disposes contribution listeners, async eligibility, overlays, terrain, rasters, bounds and diagnostics before the Surface Adapter removes the map. `releaseMap(map, failure?)` preserves the original terminal error from acquisition, map/camera or shared-renderer failure; only the controls module's private acquisition-cancellation sentinel, ordinary replacement and teardown publish idle. An external `AbortError` from the loader, map, camera or renderer remains a failure regardless of its name.
- `workspace-map-contribution-adapter.ts` defines the immutable `WorkspaceMapContributionSnapshot` and required `read(runtime)` adapter operation, with optional terrain loading and view-bounds publication. Snapshot Target geometry remains queried through the read-only Scene role, avoiding a mirrored Scene. Both edition adapters suppress Target interaction overlays in overview without changing their authority. The Desktop factory mounts `desktop-workspace-map-contribution-adapter.ts`, which reads current LiDAR/terrain/targets and publishes LiDAR bounds. The browser factory mounts `web/browser-workspace-map-contribution-adapter.ts`, which explicitly supplies empty LiDAR and terrain, with targets from shared presentation and no Desktop runtime imports. The runtime dependency graph assertion excludes erased type-only edges without weakening the repository's general architecture policies.
- `app/canvas-map-surface/workspace-generation-reconciler.ts` supplies the app-side replacement protocol. It calls the coordinator's synchronous disconnect before Canvas delegation and returns an opaque ticket that alone may queue one later current-snapshot read after a successful or pre-hydration-rejected replacement. It never waits for that disconnect before asking the coordinator to activate, preserving the coordinator's retained-cleanup ownership and avoiding promise back-edges. A successor replacement, disposal, or stale ticket invalidates queued work before it can create a stale map. Terminal reconciler disposal normally observes its own ignored rejection; when disposal starts inside a coordinator-owned callback, the coordinator's narrow lifecycle observation query identifies that exact already-observed Promise so only one diagnostic is emitted while explicit callers still receive the rejection.
- `app/map-layers/bands.ts` is the single semantic order seam for Canopi-owned MapLibre layers. Its stable descriptor bands are basemap, ordered LiDAR, terrain/geographic reference, the shared scene, then panel Target interaction overlays. Source, data, paint, visibility, and failure policy remain with their existing contribution modules. The reconciler validates the complete descriptor list before mutation, reads public `getLayersOrder()` because `getStyle()` serialization omits custom layers, and applies only required `moveLayer()` operations. Missing optional layers are ignored, already ordered stacks are no-ops, and order changes never recreate the canonical custom layer. Keep new MapLibre contribution IDs in its descriptor composition instead of adding insertion-candidate lists.
- The lazy import boundary around `maplibre-gl` should stay inside the MapLibre Host/loader path for bundle size.
- MapLibre 6 uses namespace exports and a separately bundled module worker. `maplibre/loader.ts` owns the one-time `setWorkerUrl()` call before exposing the shared module. Import its worker with Vite's `?worker&url`, not plain `?url`: the latter leaves the worker's sibling-module imports unresolved in production. Keep failed loads retryable. The real-library attribution regression protects the sanitizer fix introduced in 6.4.1.

## Camera And Projection

- The runtime works in metres in the session plane (`canvas/session-plane.ts`): local Mercator, x east, y south, scaled at its origin latitude, so it is an exact affine image of the map. The origin is the centre of the Design's objects (empty Design: the last view, else lon 13 lat 23). The scene store owns the plane; `CanvasQuerySurface.sessionPlane` publishes it. See [ADR 0001](../adr/0001-geolocated-map-canvas.md).
- `maplibre/workspace-camera.ts` implements the renderer-neutral `WorkspaceCameraOwner` for the shared workspace. It starts with detached `CameraController` behavior, then its narrow attachment control (`{ map, readOrigin }`) transfers the current plane viewport to one MapLibre map and publishes every accepted live `move` or `resize` frame through the same stable signal. It reads the session plane origin live on every frame; `attachment.refreshOrigin()` republishes the plane viewport after the origin changes while the map stays where it is. The composition calls it whenever the runtime publishes a new plane. Navigation commands target only the attached map. The owner combines the zoom-0 latitude scale with single-world screen coverage and learns any stricter minimum reported by MapLibre's public zoom state. Detach, replacement, projection rejection, and attachment errors fence stale callbacks, remove listeners, and retain the last valid frame for the map-unavailable state. The attachment owner does not create or remove the map.
- **Re-origin.** `canvas/runtime/scene-runtime/reorigin.ts` watches settled site-scale frames. When the view centre is more than 10 km from the plane origin it rebuilds the plane at the view centre through one reprojector applied to the scene store, every undo command, the clipboard and the viewport (`reprojectViewport`). Remembered positions re-project from their stored lon/lat; nothing is dirtied or recorded.
- The shared workspace coordinator and camera owner are the production camera and MapLibre owner in both editions. Do not mount a standalone map surface, synchronization effect, or second camera beside this composition.
- The in-canvas map is non-interactive and never mutates document or canvas state. Camera movement, fit and place search never move design objects.
- The map is north-up. There is no bearing anywhere in projection, camera, overlays or Target projection.
- `desktop/web/src/canvas/projection.ts` holds the shared local-Mercator math (`worldToGeo`, `geoToWorld`, zoom/scale conversion, viewport helpers); `canvas/maplibre-camera.ts` converts a plane viewport into a MapLibre centre/zoom. Do not keep separate projection math, zoom shortcuts, or equirectangular fallbacks in surface or overlay code.
- Exact sync is correctness-critical. Do not add camera deadbands or tolerances that can suppress tiny pan/zoom changes.
- Screen-lock validation is the standard: the same geographic point must land on the same screen pixel in canvas and map projections.
- Maps are pan/zoom-only. Do not expose MapLibre compass controls or drag/touch rotation unless map rotation returns through an explicit product decision.
- A settled camera (750 ms without change) reports its view centre and zoom through the composition's `onViewSettled`; both editions store it as the `last_view` setting (`app/canvas-map-surface/last-view.ts`). Fitting an empty Design centres the plane origin at the last view's zoom.

## Surface Shape

- Keep map-backed surface adapters thin. The MapLibre Host owns low-level setup, resize observation, keyed rebuild teardown, and final removal; the MapLibre Surface Adapter owns typed map access and map-lifetime cleanup; surface-specific adapters own snapshots, overlays, markers, terrain, and presentation state.
- Helper modules under `desktop/web/src/maplibre/` own MapLibre loading/types, basemap presentation, overlay coordination, terrain loading, and terrain diff/apply behavior.
- Dev diagnostics (`publishMapDiagnostics`) derive from the map frame, not ad hoc surface math.
- Rendered map overlays consume the pure Target map projection seam in `desktop/web/src/target/` instead of resolving Target identity themselves.

## Layers And Settings

- Map layer visibility and opacity live in the map layer store (`mapLayers`), never in `canvas-settings` scene-layer mirrors.
- `gridVisible` is separate canvas chrome and must not be coupled to the Basemap row.
- `activeLayerName` can be any layer string used by scene and terrain layer UI.
- Web Edition has no terrain contours, hillshade, local raster display, offline tile download, service-worker tile precache or offline map promise ([ADR 0005](../adr/0005-web-edition-scope.md)).
- Canopi has no app-managed offline tile downloader or cache on desktop or Web. MapLibre reads its configured live sources; do not reintroduce a parallel Tauri tile store without a product and cache/update decision.
- Canvas Layer Presentation (`app/canvas-layer-presentation/presentation.ts`) turns scene layers and the map layer store into Layers rows. Site references are Basemap (style choice, opacity), Satellite (provider choice, Google key field when Google, opacity), the Design's LiDAR items, Contours and Hillshade; Web shows only Basemap and Satellite. Map readiness callers use its `hasVisibleMapLayer`.
- Map snapshots read the store directly (`readWorkspaceBackgroundPresentation`, `mapTerrainStateOf`); do not build Scene layer rows or clone geometry for map settings. Empty or disabled Target overlays clear their map layers without querying Scene geometry. Nonempty overlays still read current geometry for every sync.
- Terrain paint-only changes, such as opacity and theme, should stay incremental through `maplibre/terrain-sync.ts`.
- Rebuild terrain sources/layers only when source-shape inputs change.

## LiDAR Raster Band

- LiDAR source and analysis rasters render above the basemap and below terrain/geographic references, the shared scene and interaction overlays. `maplibre/raster-display/adapter.ts` (`createRasterDisplay`) is the only owner of upstream `maplibre-gl-raster` objects: one `LayerManager` per live map with the `cog-tiler-wasm` engine, pool-backed `loadCogTiler`, in-memory `loadMosaic` for multi-asset items, and refused main-thread auto-statistics. Layer IDs change with the displayed generation; opacity is paint-only; `dispose()` removes layers, sources, protocol and listeners and releases the pool client. The engine ignores abort signals and waits for `isStyleLoaded()`, so relevance filtering lives in the pool (`tileIsRelevant`) and the adapter nudges the manager on map `idle`/`sourcedata`.
- `maplibre/raster-display/pool.ts` owns two module-worker lanes shared by the map and Data Library previews, a 128 MiB lane-wide decoded LRU, newest-first dispatch and dropping of queued off-viewport tiles. `app/canvas-map-surface/workspace-map-contributions.ts` syncs the raster display (a failed layer is omitted passively) and `layer-stack.ts` restores the ordered band after each change.
- `app/lidar/display.ts` owns the `lidar_display_descriptor` store, per-kind styles and `lidarDisplayLayers`; the Desktop contribution adapter joins it with `readCurrentLidarPresentation` (`app/lidar/library-store.ts`). Visibility, opacity and order are Design Edits (`app/design-edit/lidar.ts`), not settings.
- Display COGs are served by the scoped Tauri asset protocol under `$APPDATA/lidar/display-cog/*.tif` only; staging, job scratch, originals and numeric rasters stay webview-inaccessible. `script-src` admits `'wasm-unsafe-eval'` for the WASM engine, and `connect-src` admits `asset:` and `http://asset.localhost` for worker range reads. The Web build must not contain the raster engine (`scripts/check-web-build-boundaries.mjs`).
- Diagnostics are opt-in: `localStorage['canopi.rasterDiagnostics']='1'` exposes `window.__CANOPI_RASTER_DIAGNOSTICS__`.
- LiDAR coverage and Return use the live Canvas viewport command surface, not a map-only `fitBounds` override. Coverage converts all four WGS84 corners through the session plane, then asks the shared workspace camera to fit the resulting local-metre bounds with 48 CSS pixels of padding and the scale equivalent of MapLibre zoom 18. Repeated coverage requests retain the first session-bound bookmark; Return restores it.
- Passive LiDAR display failures degrade silently: an unready descriptor, engine failure or unavailable library entity omits its contribution while the rest of the band keeps rendering.

## Tauri And Network

- Review CSP in `tauri.conf.json` when adding tile or image sources; connection and image directives currently allow HTTPS sources plus the scoped asset protocol for LiDAR display COGs. Keep native asset access restricted to the image cache and published display COGs.
- MapLibre's worker is emitted as a self-hosted asset by Vite. Keep both `worker-src` and the WebKit fallback `child-src` admitting self-hosted workers and `blob:`; other canvas/PDF/terrain workers still use blob URLs. Never broaden CSP to compensate for a missing worker bundle.
- Linux desktop startup sets `WEBKIT_DISABLE_DMABUF_RENDERER=1` before Tauri initializes WebKitGTK. Keep this in process startup, not in developer shell instructions, because MapLibre/WebGL can freeze the WebKitGTK webview on affected systems when the default DMA-BUF renderer is used.
- Blocking HTTP/file work must run through the managed Native Operation Executor: use `Network` for remote requests and `Local` for local file work. Direct `spawn_blocking` calls belong only in `desktop/src/native_operation.rs`; see the [executor guide](build-release.md#native-operation-executor).
- All `ureq` calls must set global timeouts and response size limits.
- For large binary data, prefer `tauri::ipc::Response::new(bytes)` over JSON serialization.
