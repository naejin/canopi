# MapLibre Integration

Use this guide when changing MapLibre surfaces, basemap rendering, terrain layers, map/canvas projection, or map overlay behavior.

## Ownership

- MapLibre is a derived visualization layer, not a document authority.
- Map layers render scene/document state; they do not own or mutate it.
- Map surfaces and readiness/status UI consume the Location Workbench projection of the Design spatial frame; saved pins and the Canvas Map Surface still require confirmed placement. Do not import Design Session state directly for location presentation.
- `maplibre/host.ts` owns shared MapLibre resource lifetime for migrated map-backed surfaces: lazy loading, map creation, resize observation, keyed rebuild teardown, preserved view state, initialization failure callbacks, and final removal. The host must not import app-owned Design, Location, Target Presentation, terrain, or canvas authority.
- The host snapshots a constructor call's direct container children and class names. Constructor failure and every later map-removal path roll back only that synchronous identity/class delta; do not select broad MapLibre CSS classes or remove pre-existing or later app-owned DOM.
- `maplibre/surface-adapter.ts` is the typed adapter seam above the MapLibre Host. Production map-backed surfaces should request map lifetime through the MapLibre Surface Adapter so typed map access, map-lifetime cleanup callbacks, and event listener cleanup stay out of app/components code.
- Keep direct `maplibre-gl` imports, Map/Marker/Bounds construction, basemap style construction, and control construction in low-level modules under `desktop/web/src/maplibre/` or in tests.
- In-canvas MapLibre remains isolated behind the Canvas Map Surface adapter and the MapLibre Host. Do not scatter MapLibre ownership across canvas runtime or renderers.
- `WorkspaceMapControls` performs the browser WebGL2 preflight before attaching the MapLibre surface. An unavailable context rejects map admission early so `RendererHost` can select Canvas2D without a partially constructed MapLibre map or its browser listeners.
- Location map editing uses the MapLibre Surface Adapter for map lifetime. `app/location/coordinate-workbench.ts` owns one lazy Design Edit placement transaction; search results, map clicks, and the explicit map-center action update its complete-frame preview. Confirm commits once, while Cancel, Escape, unmount, or Design replacement aborts. `app/location/map-editing.ts` owns map interaction and pin projection without acquiring document authority.
- Web Edition v1 omits visible Location editing entirely. Do not mount a Web Location map, coordinate form, or map-picking workflow, and do not import `app/location/coordinate-workbench.ts` from Web sources. The required `.canopi` spatial frame round-trips in Web. The Web Canvas workspace displays its street basemap only when placement is confirmed; it does not add Location editing. See [ADR 0013](../adr/0013-web-edition-map-scope.md) and [ADR 0016](../adr/0016-web-edition-omits-geocoding.md).
- [ADR 0024](../adr/0024-shared-canvas-pdf-export.md) defers all map backgrounds beyond Canvas PDF v1 while retaining print selection for Design Layers. The PDF export path must not mount or capture a map surface or fetch map assets in v1, even if the interactive canvas shows a basemap. Interactive Web maps remain separate work and do not block PDF delivery. When PDF map work resumes, preserve required attribution and validate the source for print coverage, resolution, and provider terms; interactive loading alone does not establish print suitability.
- The Design Template world map uses the MapLibre Surface Adapter for map lifetime and keeps template marker creation, selection classes, fit-to-bounds, and selected-template fly-to behavior in `components/world-map/WorldMapSurface.tsx` with low-level constructors isolated under `maplibre/world-map.ts`.
- `app/canvas-map-surface/workspace-activation-snapshot.ts` reads the nullable Design session spatial authority and basemap presentation. Edition contribution adapters read the supplied query surface for live LiDAR, terrain, frame, Target, bounds, diagnostics, and readiness inputs; they do not construct a second map lifecycle or read Desktop capabilities from Web.
- `maplibre/shared-scene-layer.ts` is the qualified production custom-layer adapter. MapLibre supplies its canvas, WebGL2 context, resize, and render callback; the adapter owns only Pixi graphics resources and the retained botanical presentation. Scene updates and camera-only invalidations call `triggerRepaint()`, and drawing occurs only inside MapLibre's custom-layer callback with `clear: false`. `maplibre/scene-camera-transform.ts` derives the local-metre viewport from live MapLibre projection and rejects pitch or excessive affine residual.
- `maplibre/shared-scene-renderer.ts` composes the workspace map custom layer with the renderer-neutral bridge in `canvas/runtime/renderers/maplibre-scene.ts`, including mandatory adapter failure propagation into RendererHost. A workspace owner must also call `failActiveLayer()` when map construction fails before the custom layer initializes.
- `maplibre/workspace-map.ts` creates the non-interactive shared-workspace map shell from a source-free inline style. `app/canvas-map-surface/workspace-map-controls.ts` adapts that shell to transactional admission through one MapLibre Surface Adapter: each `createMap(signal, snapshot, sessionIdentity)` attempt retains immutable spatial/session construction facts and its own latest immutable `WorkspaceBasemapPresentation`. `updateBasemapPresentation()` is scoped to the current attempt: it normalizes opacity to `[0, 1]`, retains updates during acquisition, and is inert after release. It changes opacity with `setPaintProperty()` only; hide removes the raster layer before its source; show/style changes replace only that contribution. Provisional placement and hidden presentation never add remote source work. The raster contribution is placed immediately above the local background and before all later layers, preserving unrelated layer identity and order. Initial `style.load` admits the map only. One attempt-scoped reconciliation drain serializes later same-map style reload and presentation work: it applies the latest retained presentation, invokes one map-lifetime scene restorer only for reload work, then restores semantic order; reentrant signals are coalesced and replayed, while a failed mutation fences every later drain. The operation never calls `setStyle()`, recreates the map/camera/custom scene layer/runtime, or rereads Design/settings state. It obtains WebGL2 from the public map canvas, retains context loss or generic map failure until the coordinator installs its watcher, and delegates every final removal to the Surface Adapter. Hosted basemap and recognized contribution source errors are passive; one mutation/restoration failure flows through the existing watcher and generic map failures fail the shared backend. This adapter is the production map path in both editions.
- The shared workspace shell stays `interactive: false`. Pointer pan and wheel reach the single Scene Interaction owner, whose navigation commands target `MapLibreWorkspaceCameraOwner`; MapLibre must not install an independent drag, wheel, pinch, or pointer-capture owner. Tool/object gestures therefore mutate Scene/history only, while navigation changes the map-backed frame only. Detach restores the owner’s Canvas2D navigation fallback.
- `app/canvas-map-surface/workspace-activation.ts` owns transactional shared-workspace admission. `activate(snapshot)` binds one opaque Design session identity, immutable map/spatial facts, an owned latest basemap presentation, and optional maximum world extent to a generation. `updateBasemapPresentation()` buffers the latest value for the newest acquiring generation and forwards only after its controls attempt exists; it is inert for a superseded/disconnected generation, terminal fallback, or as soon as terminal teardown is requested, and cannot recreate a map, camera, custom layer, or Scene runtime. Map creation, WebGL2 acquisition, canonical custom-layer initialization and attachment, and accepted camera attachment must all complete before the first `SceneCanvasRuntime.init()` may select `maplibre-pixi`; remote tile readiness is not an admission condition. `requestGenerationDisconnect()` is intentionally non-async: it publishes one retained generation settlement before aborting acquisition, fences callbacks, detaches camera ownership, and invokes layer disposal synchronously. The retained result exhaustively joins resource cleanup and any already-admitted renderer failure/failover; map removal waits for layer disposal. Repeated requests share that settlement; activation and terminal teardown join it, while one rejected settlement blocks one successor admission before a later request may recover. Resource callbacks may synchronously request another coordinator operation, and a void callback receives its real retained settlement. A child setup, disposal, initialization, or failover Promise must never adopt or await an owner operation that joins that child; direct returns are rejected as ownership violations, and wrapped or delayed back-edges are invalid by contract because JavaScript Promises cannot expose their dependency graph. Replacing A with B first removes A's restorer and failure watchers, detaches its camera, disposes its layer while the context is valid, and releases its map. It then creates B while retaining the initialized Scene runtime and renderer bridge, whose disconnected snapshot replay seeds the new layer. Equal map values with a new session identity still form a new generation. After a same-context style reload, the coordinator idempotently ensures that generation's initialized canonical layer is attached after the controls restore its bound basemap. Before-first-init failure cleans the attempted generation before Canvas2D initializes. Failure after runtime initialization cleans that generation, invokes runtime failover once, and permanently fences shared-backend restart for that coordinator. Public teardown is memoized, joins generation cleanup and pending initialization, reports their errors to every caller, then alone destroys the runtime once. The newest activation request wins; abort and generation fences reject stale map, initialization, style, camera, and failure callbacks.
- `app/canvas-map-surface/workspace-runtime-composition.ts` composes the single shared camera, MapLibre renderer backend, Canvas2D fallback, coordinator, and reconciler. `desktop-workspace-runtime.ts` and `web/browser-workspace-runtime.ts` mount it in the respective editions through `WorkspaceRuntimeMountOptions`; the final runtime container is passed straight to the composition. These factories pass retained live basemap and immutable contribution snapshots to the coordinator; updates do not create or replace map/scene resources.
- `app/canvas-map-surface/workspace-map-contributions.ts` owns the controls attempt's session-bound presentation: incremental LiDAR, terrain generation fences, panel Target overlays, semantic ordering, readiness/terrain/precision state, view bounds and diagnostics. It reconstructs from the latest captured snapshot after `style.load`, uses the same map and camera, and fences synchronous reentrant mutations and stale async terrain completion. Failed LiDAR IDs stay omitted until their source shape changes or the style reloads; terrain load/source/rebuild errors leave editing ready only after their partial contributions are removed successfully. Failed LiDAR removal (including obsolete layers) or failed terrain rollback enters the one-shot hard map failure path with the cleanup error; it must never claim passive omission while partial resources remain. Overlay sync and semantic-order failures are terminal: the manager disposes once and reports through the controls failure watcher; ordering after an async terrain rebuild stays outside passive terrain error handling. A fatal contribution failure during initial restoration rejects acquisition before watcher installation. Generation disconnect clears contribution inputs synchronously; release disposes contribution listeners, async eligibility, overlays, terrain, rasters, bounds and diagnostics before the Surface Adapter removes the map. `releaseMap(map, failure?)` preserves the original terminal error from acquisition, map/camera or shared-renderer failure; only the controls module's private acquisition-cancellation sentinel, ordinary replacement and teardown publish idle. An external `AbortError` from the loader, map, camera or renderer remains a failure regardless of its name.
- `workspace-map-contribution-adapter.ts` defines the immutable `WorkspaceMapContributionSnapshot` and required `read(runtime)` adapter operation, with optional terrain loading and view-bounds publication. Snapshot Target geometry remains queried through the read-only Scene role, avoiding a mirrored Scene. The Desktop factory mounts `desktop-workspace-map-contribution-adapter.ts`, which reads current LiDAR/terrain/targets and publishes LiDAR bounds. The browser factory mounts `web/browser-workspace-map-contribution-adapter.ts`, which explicitly supplies empty LiDAR and terrain, with targets from shared presentation and no Desktop runtime imports. The runtime dependency graph assertion excludes erased type-only edges without weakening the repository's general architecture policies.
- `app/canvas-map-surface/workspace-generation-reconciler.ts` supplies the app-side replacement protocol. It calls the coordinator's synchronous disconnect before Canvas delegation and returns an opaque ticket that alone may queue one later current-snapshot read after a successful or pre-hydration-rejected replacement. It never waits for that disconnect before asking the coordinator to activate, preserving the coordinator's retained-cleanup ownership and avoiding promise back-edges. A successor replacement, disposal, or stale ticket invalidates queued work before it can create a stale map.
- `app/canvas-map-surface/layer-stack.ts` is the single semantic order seam for Canopi-owned MapLibre layers. Its stable descriptor bands are basemap, ordered LiDAR, terrain/geographic reference, the shared scene, then panel Target interaction overlays. Source, data, paint, visibility, and failure policy remain with their existing contribution modules. The reconciler validates the complete descriptor list before mutation, reads public `getLayersOrder()` because `getStyle()` serialization omits custom layers, and applies only required `moveLayer()` operations. Missing optional layers are ignored, already ordered stacks are no-ops, and order changes never recreate the canonical custom layer. Keep new MapLibre contribution IDs in its descriptor composition instead of adding insertion-candidate lists.
- The lazy import boundary around `maplibre-gl` should stay inside the MapLibre Host/loader path for bundle size.
- MapLibre 6 uses namespace exports and a separately bundled module worker. `maplibre/loader.ts` owns the one-time `setWorkerUrl()` call before exposing the shared module. Import its worker with Vite's `?worker&url`, not plain `?url`: the latter leaves the worker's sibling-module imports unresolved in production. Keep failed loads retryable. The real-library attribution regression protects the sanitizer fix introduced in 6.4.1.

## Camera And Projection

- `maplibre/workspace-camera.ts` implements the renderer-neutral `WorkspaceCameraOwner` for the shared workspace. It starts with `CameraController` fallback behavior, then its narrow attachment control transfers the current local viewport to one MapLibre map and publishes every accepted live `move` or `resize` frame through the same stable signal. Navigation commands target only the attached map. Detach, replacement, projection rejection, and attachment errors fence stale callbacks, remove listeners, and retain the last valid local-metre frame for fallback. When an attached navigation command causes that failure, the owner reapplies the requested viewport through the Canvas2D fallback so the command is not lost. The attachment owner does not create or remove the map.
- The shared workspace coordinator and camera owner are the production camera and MapLibre owner in both editions. Do not mount a standalone Canvas Map Surface, synchronization effect, or second camera beside this composition.
- The current in-canvas basemap is non-interactive and must not mutate document or canvas state.
- Map/canvas projection is bearing-aware, Mercator-backed, and shared.
- Spatial-frame `north_bearing_deg` participates in camera derivation and world-to-geo feature projection.
- A new Design persists the canonical provisional anchor. The Location editor starts its overview at that authored anchor without a saved pin and labels the placement provisional; local-metre editing remains available. The Canvas Map Surface projects only confirmed placement, so a new Design cannot create its in-canvas MapLibre surface or issue remote source requests before explicit placement confirmation.
- `desktop/web/src/canvas/projection.ts` is the dependency-free canonical seam for local-Mercator math, scalar precision policy, and projection diagnostics. `createProjectionPrecisionSnapshot()` accepts only the already-derived physical extent in meters; it must not import Scene contracts or infer Scene geometry. MapLibre surface state and developer diagnostics both consume that snapshot; do not duplicate its threshold comparison in surface code. Consumers import only the operations and constants they need; do not add a strategy or selector until a second demonstrated implementation has a real selection seam.
- `CanvasQuerySurface.getScenePhysicalExtentMeters()` computes the current Scene’s radial physical extent through `canvas/runtime/scene-physical-extent.ts` inside SceneStore, without cloning the Scene. `maplibre/canvas-surface-state.ts` composes that scalar with the projection precision policy. Preserve design origin `(0, 0)` as the radial origin, the stable `local-mercator` projection identity, and the strict warning boundary: exactly 10 km is not a warning, while any extent above it is.
- MapLibre-facing bearing adaptation belongs in `desktop/web/src/canvas/maplibre-camera.ts`.
- Do not keep separate bearing math, zoom shortcuts, or equirectangular fallbacks in surface or overlay code.
- Exact sync is correctness-critical. Do not add camera deadbands or tolerances that can suppress tiny pan/zoom changes.
- Screen-lock validation is the standard: the same world point must land on the same screen pixel in canvas and map projections.
- User-facing MapLibre maps are pan/zoom-only while Canopi has no user map-rotation workflow. Keep zoom controls when useful, but do not expose MapLibre compass controls or drag/touch rotation unless map rotation returns through an explicit product decision.

## Surface Shape

- Keep map-backed surface adapters thin. The MapLibre Host owns low-level setup, resize observation, keyed rebuild teardown, and final removal; the MapLibre Surface Adapter owns typed map access and map-lifetime cleanup; surface-specific adapters own snapshots, overlays, markers, terrain, and presentation state.
- Helper modules under `desktop/web/src/maplibre/` own MapLibre loading/types, basemap presentation, overlay coordination, terrain loading, and terrain diff/apply behavior.
- Precision warnings and dev diagnostics derive from the projection seam, not ad hoc surface math.
- Rendered map overlays consume the pure Target map projection seam in `desktop/web/src/target/` instead of resolving Target identity themselves.

## Layers And Settings

- `layerVisibility.base` and `layerOpacity.base` mean shared hosted basemap visibility/opacity.
- `gridVisible` is separate canvas chrome and must not be coupled to the base layer row.
- `activeLayerName` can be any layer string used by scene and terrain layer UI.
- Web Edition v1 scope is street basemap only: no satellite basemap, terrain contours, hillshade, offline tile download, service-worker tile precache, or offline map promise. See `docs/adr/0013-web-edition-map-scope.md` and `docs/adr/0022-web-edition-not-offline-first.md`.
- Canopi has no app-managed offline tile downloader or cache on desktop or Web. MapLibre reads its configured live sources; do not reintroduce a parallel Tauri tile store without a product and cache/update decision.
- Contours use `layerVisibility.contours` and `layerOpacity.contours`.
- Hillshading uses `hillshadeVisible` and `hillshadeOpacity`.
- Canvas Layer Presentation bridges scene/map/terrain layer asymmetry for the Desktop `LayersPanel` adapter, Canvas shell Location Notices, and Canvas Map Surface snapshots. Map readiness callers should consume its map-surface projection instead of recomputing base/contour/hillshade visibility.
- Camera-driven map snapshots use `readCanvasMapLayerPresentation()` for settings-only map/terrain inputs; do not build Scene layer rows or clone geometry for map settings. Empty, disabled, or unlocated Target overlays clear their map layers without querying Scene geometry. Nonempty overlays still read current geometry for every sync.
- Terrain paint-only changes, such as opacity and theme, should stay incremental through `maplibre/terrain-sync.ts`.
- Rebuild terrain sources/layers only when source-shape inputs change.

## LiDAR Raster Band

- LiDAR source and analysis rasters render as MapLibre raster layers above the basemap and below terrain/geographic references, the shared scene, and interaction overlays. `app/canvas-map-surface/lidar-sync.ts` owns only source/layer creation, removal, and paint changes; `app/canvas-map-surface/layer-stack.ts` restores the ordered LiDAR band through explicit moves after contribution sync or shared style restoration. Reordering stable LiDAR IDs performs no source or paint mutation. URL, zoom-limit, or bounds changes rebuild the affected raster source, while opacity remains paint-only.
- `app/canvas-map-surface/lidar.ts` projects Desktop joined LiDAR presentation into map layers through `lidarMapLayers`; it re-exports the platform-neutral `lidar-sync.ts` types and diff/apply functions for existing mounted callers. Shared/browser code imports `lidar-sync.ts` directly. `classifyLidarSync` classifies each update into add/remove/paint actions. Opacity changes are paint-only (`setPaintProperty raster-opacity`) so opacity drags never reload tiles; tile-template changes remove and re-add. Visibility toggles are document presentation edits (`app/design-edit/lidar.ts`), not settings keys.
- LiDAR presentation joins live behind `app/lidar/library-store.ts` (`readCurrentLidarPresentation`); the map snapshot must read the design through that seam, not through `document-session/store` directly — the snapshot is policy-forbidden from importing the store.
- LiDAR display tiles are served by the scoped Tauri asset protocol under `$APPDATA/lidar/display/**`. Import review additionally admits only `preview-before.png`, `preview-after.png`, and their two-digit decision variants inside one job directory; job scratch, originals and prepared numeric rasters remain webview-inaccessible. `app/lidar/tile-urls.ts` converts the Rust-returned filesystem path template (`{z}_{x}_{y}.png` marker) into the platform asset URL; `connect-src` in `desktop/tauri.conf.json` admits `asset:` and `http://asset.localhost` for MapLibre worker tile fetches.
- Native display rows retain EPSG:3857 bounds. The presentation boundary converts them once to WGS84 `[west, south, east, north]` before the frontend supplies MapLibre source bounds. Never pass metre coordinates through the `LidarTileset.bounds` contract.
- LiDAR coverage and Return use the live Canvas viewport command surface, not a map-only `fitBounds` override. Coverage requires confirmed placement, converts all four WGS84 corners through the Design's bearing-aware local frame, then asks the shared workspace camera to fit the resulting local-metre bounds with 48 CSS pixels of padding and the scale equivalent of MapLibre zoom 18. Repeated coverage requests retain the first session-bound bookmark; Return restores it.
- Passive LiDAR display failures degrade silently: missing tiles, engine failures, or unavailable library entities omit their contribution while the rest of the band keeps rendering. `hasVisibleMapLayer` includes visible LiDAR layers that actually have tiles so the surface mounts when the first band entry becomes renderable.

## Tauri And Network

- Review CSP in `tauri.conf.json` when adding tile or image sources; connection and image directives currently allow HTTPS sources plus the scoped asset protocol for LiDAR display tiles. Keep native asset access restricted to the image cache and the LiDAR display cache.
- MapLibre's worker is emitted as a self-hosted asset by Vite. Keep both `worker-src` and the WebKit fallback `child-src` admitting self-hosted workers and `blob:`; other canvas/PDF/terrain workers still use blob URLs. Never broaden CSP to compensate for a missing worker bundle.
- Linux desktop startup sets `WEBKIT_DISABLE_DMABUF_RENDERER=1` before Tauri initializes WebKitGTK. Keep this in process startup, not in developer shell instructions, because MapLibre/WebGL can freeze the WebKitGTK webview on affected systems when the default DMA-BUF renderer is used.
- Blocking HTTP/file work must run through the managed Native Operation Executor: use `Network` for remote requests and `Local` for local file work. Direct `spawn_blocking` calls belong only in `desktop/src/native_operation.rs`; see the [executor guide](build-release.md#native-operation-executor).
- All `ureq` calls must set global timeouts and response size limits.
- For large binary data, prefer `tauri::ipc::Response::new(bytes)` over JSON serialization.
