## Required repairs

1. **P1 — Collection reads deadlock.** mod.rs:749 holds CatalogueGuard until function return; :819 calls layer_history, which acquires the same mutex at :721. A real layer_collection call on an empty layer timed out. Read history under the existing connection, retaining a consistent snapshot, and exercise this public read surface.

2. **P1 — Edit completion and the visible selection are not connected reliably.** mod.rs:1100 spawns an edit and returns acknowledgement; settlement logs errors and discards library_snapshot output. actions.ts:162 refreshes immediately; library-store.ts:49/77 only keeps polling for import/analysis jobs. A slow member edit can finish after polling stops, with no map update or reported error. In LidarLayersSection.tsx:93-143, History is loaded only when opened, the effect skips history mode, and late collection/history answers are never fenced against the selection/head. SourcePriorityList's Undo uses collection.layer_id, so a late response can even target the previous layer while the header shows the new one. Use an explicit completion result through the existing async command/executor seam, refresh selected source/history/map state after settlement, fence stale responses, and keep failed-edit messages visible. Busy/loading controls must not send edits without the snapshot the user actually saw. No event bus or new scheduler is needed.

3. **P1 — Published statistics use different composition semantics.** import.rs:3332-3450 builds incoming members with the obsolete Add/ReplaceOverlap role; CollectionReader::new at generation.rs:306 reverses them but retains that role. Persisted rows are later loaded as Replace. A full-cover import of 9 above 5 reads back as 9 but publishes min/max 5/5. Construct every new ordered occurrence with topmost-valid semantics, including the measuring/review path. Preserve old role semantics only for historical reads.

4. **P1 — Import admission is incomplete.** stage_import checks every first-batch source against an absent layer CRS, so equal-coordinate EPSG:3857 and EPSG:4326 inputs are accepted together. stage_source_samples discards the valid sample count, allowing all-NoData members. prepare_apply/apply_import permit publication of the compatible subset of a rejected batch; the UI disabling Add sources is the only guard. Review/Apply envelope checks use manifest.grid (the fixed original lattice dimensions) plus incoming inputs, omitting prior ordered members. An actual 32,000,016-cell collection was admitted under the unchanged 25M limit. Validate a batch against one common interpretation, reject each zero-valid source by name, recheck whole-batch admission in the backend, and measure the current composition's extent separately from its fixed coordinate anchor. Do not increase limits.

5. **P1 — Transition can alter accepted historical data.** collection.rs:208 describes a sparse previous composition using its original manifest grid dimensions; generation.rs:202-215 clips it to that box. A valid chunk at x=2048 becomes entirely invalid through the adapter although the original chunk reader returns all 16 samples. Separately, import.rs:3478 follows head.base_generation_id instead of wrapping the actual accepted head: a historical overlay valued 7 becomes the older base valued 5 after adding a new source. Preserve the latest head itself as the indivisible member and retain its signed sparse chunk extent/coordinates through the existing reader. No re-encoding or historical source reconstruction is needed.

6. **P1 — Slope has three remaining correctness holes.** analysis.rs:108-116 only accepts a direct source COG as a representative raster; after Undo leaves only Previous composition, valid slope input fails with 'generation has no stored raster to inspect'. A queued job whose captured source is superseded returns a plain publication error, while mod.rs:1700 only coalesces Ok(stale=true); the latest-head refresh can be lost. presentation.rs:80-98 never compares source and result heads and reports old results Ready after failed/cancelled refresh or restart. A restart after source publication reproduced Ready with no stale detail. Reuse the preserved reader for eligibility, route superseded work through the existing stale/coalescing outcome, and derive readiness from source identity, including empty composition and startup. Retain last-good results with truthful stale/unavailable state.

7. **P1 — Undo/history boundaries and restore equality are inconsistent.** First import exposes can_undo=false; a direct Undo reaches empty, but another Undo reinstates the import. Restore only compares generation IDs and republishes identical ordered member identities. History infers operation from interpretation lists and the undo cursor, so labels such as import/remove can describe an Undo, and duplicate occurrences are conflated. Represent the empty baseline/exhausted Undo consistently, compare ordered occurrence identities for restore no-ops, and record the real operation instead of guessing it. Keep this as metadata and local history logic.

8. **P2 — Source-region facts reread the first block.** generation.rs:1227 uses chunk-local clip_x0/clip_y0 as source pixel coordinates without the chunk origin offset. A 2048x1 source with 1024 invalid cells followed by 1024 valid sevens has exact review coverage 1024 but stored source-list coverage 0/range 0-0. catalogue.rs:1069 also includes zero-valid blocks in extrema. Fix the source-coordinate translation and exclude zero-valid blocks from numeric extrema. This is separate from the explicitly deferred source preview-range sentinel behavior tracked in canopi-jv8a.2.

9. **P2 — Bound the incremental read surfaces already promised.** collection_members and history return complete vectors; layer_collection bundles every version and its membership into every source-list refresh. Each new tile reader resolves every current member. The 16-file selection limit does not bound lifetime membership/history. Keep this repair narrow: use existing catalogue indexes/region queries and small member/history pages for incremental consumers, and select intersecting members for bounded reads. A short-lived member vector during a mutation is not itself a reason for a generic pagination layer. No new cache architecture, custom spatial engine or capacity campaign is required.

10. **P2 — Finish the existing UI contract with existing data.** The source list shows a 12-character interpretation hash despite lidar_sources.original_filename already being populated (import.rs:937). Use that stored name through the existing interpretation/source relation; no schema migration is needed for the available original name. HistoryDetail shows only operation/time/cell count, omitting the required unique version cue. The import confirmation still renders obsolete uncovered/overlap/invalid counters at LidarLayersSection.tsx:449. Add the small identity cue and remove the old counters; keep the accepted dock layout and Add sources interaction.

11. **P2 — Propagate cancellation through the compatibility read.** collection.rs:237 calls compat_lease with AtomicBool::new(false), so a cold legacy conversion ignores the real import/tile/analysis cancellation token. Carry the caller's token through the existing load/adapter chain and check cancellation at the publication boundary. This needs no new cancellation service.
