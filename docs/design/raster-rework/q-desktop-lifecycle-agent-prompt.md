## L1 — cancellation is a persistent state, not a message

Worker state is run-scoped: running → cancelling → settled, with no transition back. A cancellation for another nonce has no effect. A valid cancellation sets state before settling pending requests. After every asynchronous boundary (including module import and WASM initialization), recheck state before constructing a decoder, issuing any read, decoding or publishing success. Late work can only dispose its acquired resource; it cannot resume the cancelled run. Disposal is once per acquired stream; cancellation before acquisition must not consume the later stream's disposal obligation. A disposal failure is reported as an instrument problem, not silently hidden behind success.

The WebView uses the same run identity/state to reject stale messages and replies, clear deadline and grace timers and terminate its worker once. Missing/wrong nonce is not accepted as the current run. Cancellation stops new native invocations immediately, including an already queued message handler that resumes later. Keep the five-second cleanup target: cooperative release first, then terminate the worker/owned host process if necessary. Timeout/cancellation produces an instrument failure, not a scientific mismatch. Existing successful decode and transfer behavior stays unchanged.

Native reservation ownership must span admission, executor waiting, running I/O and settlement. Use a drop-safe ownership guard or equivalent single owner so an executor refusal, dropped waiting future, panic, I/O error and normal completion each release reservation/accounting exactly once. Do not depend on a closure running in order to release a queued reservation. Teardown marks cancellation before any queued operation can start; the start transition checks it under the state lock and refuses I/O after revocation. Running I/O keeps its descriptor until it actually settles. Keep two active/32 waiting, positional reads, nonce checks and host-owned labels. Release descriptors once the last outstanding request settles; preserve immutable metadata for evidence. Native filesystem work, including evidence publication, remains executor-backed. Do not weaken the production executor's own cancellation semantics.

Tests must exercise the actual worker module with controllable import/read dependencies, the WebView lifecycle and the command's shared adapter with the real executor. Extract the existing command body into a testable internal operation if necessary; both command and test call it. Required controls: cancel before import resolves, during WASM init and during an awaited read; wrong-run cancellation; late read/success after settle; double cancellation; a stream acquired after cancellation is freed; dropped queued caller releases capacity/identity; teardown with two running plus queued reads prevents queued I/O; error/panic cannot leak a reservation. Barriers must establish that work is genuinely waiting/running, not merely manually insert an ID into a set. Expected postcondition includes actual read count, outstanding count and resource release, not just a closed flag.
