Status: proposed — decision-complete next foundation design; executable through the paired user-forwarded assignment, not implemented.
Tracking: foundation `canopi-jv8a`, epic `canopi-j571`; the implementer creates one scoped child for this batch. Accepted predecessor: `canopi-jv8a.1` at `a5fc7d7b`.

## 1. Outcome and authority

Replace full-grid generation construction and its downstream readers with bounded sparse processing **while keeping the existing import review/Apply, undo, map presentation and slope UI usable**. Deliver the whole caller migration, not a storage module with unusable consumers. The user has delegated architecture to the main agent; the implementer owns routine implementation and in-scope repairs. One implementation batch, one consolidated delivery, independent review through the user.

This assignment deliberately combines the storage and caller dependencies formerly listed as N1–N3/native D in the long-term plan. It does **not** implement the later single-action import UI, definition editor, inspection UI, Web Location, satellite controls or new analyses. Existing commands must read new heads safely; the former suggestion to make legacy UI commands reject new heads is superseded for this transition. Approved HTML `0e696722` remains the later UI authority, not a reason to redesign the current UI now.

Scientific compatibility remains the accepted **Float32 conversion** contract from G1–G5. The native window interface can expose f64 values converted from those persisted samples, but that does not restore discarded precision. Lossless Float64/large-integer admission is a later explicit migration, not a hidden promise of this batch. Keep the pinned `wbgeotiff` dependency and GDAL preparation/projection/slope; no engine search, dependency upgrade, Q work, Python migration or new evaluation framework. This uses the native core selected by GeoLibre; it does not claim the whole GeoLibre toolkit has been integrated.

## 3. Storage: explicit validity, sparse blocks, immutable history

### Lattice and block encoding

A layer has one fixed north-up lattice: CRS, pixel sizes and reference origin chosen by its first accepted source. Record this separately from each generation's occupied bounding extent. Extend left/up using signed i64 cell/block coordinates, Euclidean division for negative block coordinates and checked arithmetic. Never move the layer anchor when the bounding extent changes. Existing `RasterGrid` descriptors may still represent a bounded source/window; do not force a sparse global extent through u32 casts. Reject non-finite, fractional/misaligned or unrepresentable geometry explicitly, not by saturation. Display bounds are summaries, not permission to allocate their area.

Choose **1024×1024 blocks**, `f32-mask-block-v1`, using existing simple raw encodings rather than implementing another TIFF writer. Each immutable block asset directory has a small versioned manifest, `values.raw` (little-endian Float32, row-major) and `valid.bin` (one byte per cell, exactly 0 or 1). Blocks are padded to this fixed size; outside-source padding is invalid. Asset identity is SHA-256 over an explicit version/shape prefix and both byte streams. Validate version, exact lengths and digest before publishing/reusing; do not trust filename identity alone. Store relative library-owned asset references, never arbitrary frontend paths. No compression or new runtime dependency is needed.

Prepared member blocks preserve source Float32 bytes and validity semantics. Entirely invalid blocks may be omitted: originals remain the exact source authority, and invalid sample payloads have no numeric meaning in the window API. Resolved/result blocks canonicalize invalid samples to zero with mask=0, never infer validity from zero or a finite sentinel. Valid zero/negative values survive even if equal to a different member's NoData marker. The source's own declared NoData applies only when preparing that source. Unknown future asset versions fail explicitly.

The store is sparse by **occupied block**, not by OS sparse-file holes. No union-sized `set_len`, raster file, validity bitmap, VRT source list or traversal of absent coordinates. Source preparation can scan its source rectangle once; generation work enumerates indexed occupied blocks only. A 400M-cell contiguous source uses about 400 blocks, while two small sources a million pixels apart use only their occupied blocks.

### Catalogue representation and authority

Keep original objects, interpretation IDs, generation IDs, member occurrence order/job IDs, heads and analysis definitions. Add storage discriminators `legacy-dense-v1` and `member-window-v1` for source generations, and `legacy-dense-v1` / `block-window-v1` for result generations. Add paged tables for prepared-interpretation block references, generation occupied block references, asset metadata and per-block aggregates (valid count, finite min/max and f64 sum). Use unique keys on owner + block coordinates; do not store individual pixels in SQLite. An ordered occurrence is identified by generation + ordinal, not by interpretation hash. Footprint candidates must be constrained by layer/generation and then checked against exact integer extents; the existing R-tree is a candidate accelerator, not validity authority.

Ordered members are the authority for composition/history. A published generation's resolved blocks are immutable materialized derivatives of exactly that sequence. They make read latency independent of history length and must be verified before Ready. Unchanged block assets are shared by hash; replacing a small source must not rewrite the entire union or duplicate all prior raster bytes. Copying/paging block-reference metadata is acceptable. Recompute touched blocks by replay, not by guessing the winner from hashes. A missing/corrupt referenced block is unavailable/corrupt, **not** implicit NoData; absent index entries mean invalid coverage. Rebuild corrupt reproducible assets only from verified authoritative inputs, under a job owner, without changing scientific generation identity.

Large member/block inventories live in paged rows, not `manifest_json`. Manifest v1 records format/lattice/encoding, engine identity, interpretation policy and index identity. List-valued old manifests remain a legacy read format. Aggregate final generation statistics from the final resolved blocks after precedence: overwritten extrema must disappear. This corrects the old accumulation of superseded extrema for new publications. Do not silently edit existing legacy generation statistics or broaden `canopi-jv8a.2` (source-range discrepancy) into unrelated source behavior changes.

For old heads whose durable members exist, boundedly adapt those members. For old heads without reconstructible member history, retain an explicit immutable `base_generation_id` reference to the legacy head and overlay new occurrences; never fabricate historical members. New-job undo can restore that base. Attempts to undo unreconstructible older jobs retain the existing explicit refusal, preserving the old head. No cyclic base chains: new generations reference the original opaque legacy base, not the preceding new generation.

### Migration and legacy access

Use the next available catalogue version (v7 if still unused). Before migration, make a SQLite-consistent backup including WAL data using the existing SQLite facilities (`VACUUM INTO` with a bound destination is acceptable outside a transaction), sync it and record its path. Never copy only a live main DB file. Migrate atomically, retaining foreign keys/indexes and checking their integrity. Legacy mosaic/coverage/result paths become nullable with storage-specific constraints; do not insert fake paths to satisfy NOT NULL. An unsupported newer schema is rejected before writes. Interrupted migration leaves the original version usable or a complete migrated database, not a partial schema.

Legacy numeric adapters seek bounded rows from existing raw/mask files. When only a legacy TIFF exists, prepare a controlled derivative once per job/cache lease and read windows through the accepted native reader; apply the authoritative legacy validity mask independently of the derivative's NoData tag. Do not reprepare for every window. Old Ready generations remain readable and unchanged; mixed legacy/new histories work. Abort incompatible pre-upgrade awaiting-review scratch jobs with a clear reimport message; do not approve or resume stale serialized plans. The existing review UI is still the reimport route. `.canopi` format and presentation IDs remain unchanged.

## 4. One resolver for all numeric consumers

Implement a private cohesive generation module with three operations (names are illustrative, contracts are fixed): open an immutable generation snapshot/lease; read a half-open native-resolution window; page occupied block coordinates/aggregates. Windows are at most 1024×1024, plus an explicitly requested one-cell analysis halo on each edge (maximum 1026×1026). Out-of-extent and absent-block cells are invalid. Return values, exact mask and grid identity; no full raster crosses IPC. Close file leases deterministically. Cancellation is checked between bounded reads and before child work.

Unpublished review candidates use the same resolver over a staged ordered-member sequence. Replay each intersecting member in ordinal order: `add` fills currently invalid cells, `replace` paints valid incoming cells anywhere, `replace-overlap` paints only currently valid cells; invalid incoming cells never erase prior coverage. Keep `replace-overlap` available to the existing UI and history during this compatibility transition; only the future single-action UI stops creating it. Both flags false is a no-op. Reimport A after B is a distinct occurrence even if A's bytes are deduplicated. Undo removes occurrences belonging to that import job, then replays remaining order.

Review classification unions incoming validity within each block and compares it once with the starting head, so overlapping selected files do not double-count. Preserve existing count meanings, including `invalid_cells = checked union-envelope cell count - unique incoming valid count`; compute the former arithmetically without visiting the empty gap. Unknown/overflow counts fail rather than wrap. Preserve selected source order. Preserve the current no-change behavior for add-only imports adding no coverage; explicit replacement still records its occurrence even if samples happen to match, preserving targeted undo.

## 5. Import, publication and lifetime

Stage source objects sequentially, stream original copy/hash and prepared blocks, page member metadata, and release each temporary COG before preparing the next source. Persist bounded source facts/preview plans on disk. The existing IPC source selection/review lists remain metadata rather than raster payloads; do not duplicate them inside block jobs or copy all member/block records into memory. If existing transport limits are reached, return a named metadata-size error rather than inventing another raster pixel/file-count ceiling.

The library owns one exclusive **heavy raster job** lease shared by staging, decision-preview computation, apply, undo, analysis and legacy preparation. Awaiting user review releases it. Apply reacquires it and rechecks the planned starting head. Additional user heavy submissions return busy promptly without creating running work; automatic refresh keeps only the latest pending generation per definition in durable job metadata and schedules it when the lease is free. Do not hold a Native Operation Executor permit waiting for another operation queued behind it. Reuse its execution mechanisms and current cancellation signal path; no new blocking pool.

Each write job owns an exclusive scratch root on the destination volume. A guard removes its unpublished artifacts on error/cancellation, including the inherited analysis staging case `canopi-jv8a.3`, now in scope because analysis publication is being migrated. Never delete shared accepted member/block assets as job cleanup. Deletion revokes new reads, cancels relevant work and defers physical reclamation until leases settle; it must not recreate deleted definitions through a late result. Treat `canopi-jv8a.3` as linked work, not a competing implementation by another agent.

Prepare block files/manifests, validate them, sync files and their containing directories using platform-supported durability, then rename owned staging into immutable storage. Large block/member index rows may be inserted in bounded transactions as **unpublished** rows that readers cannot select. The final short transaction verifies entity existence, job state and expected head, marks the generation published, advances head and records job completion together. It does not copy millions of rows or do raster I/O. Set appropriate SQLite durable commit settings; document and test platform guarantees rather than claiming power-loss safety from rename alone. Startup removes only inventoried unpublished jobs/rows/assets and never originals, accepted history or leased cache entries. Publication is idempotent by job ID: crash after commit yields readable success on restart, not a duplicate generation. Cancellation before commit publishes nothing; cancellation after successful commit cannot report that publication failed.

Numeric Ready is independent of display-cache preparation. A tile failure leaves a sound accepted head readable, with display unavailable/retryable rather than rolling back numeric publication. Keep existing UI actions and status vocabulary; use its error/status surfaces for display failure, with small additive presentation fields only where required. Do not show missing data as valid or silently fall back to dense rendering.

## 6. Bounded slope through the retained engine

Resolve the input generation once. Iterate occupied core blocks, assemble each 1024×1024 core plus one-cell halo through the resolver (including adjacent member boundaries), and export only that bounded scratch raster for GDAL. Outside generation coverage and invalid samples become NaN NoData in the scratch export, so a valid finite value can never collide with the transport sentinel. This scratch convention does not rewrite member data. Pass explicit existing Horn slope settings, `-s 1`, `-p` only for percent, no edge interpolation. Crop output to the core and publish sparse result blocks; never concatenate a full result TIFF. Reuse the existing fixed-argv GDAL adapter and its cancellation/timeout controls.

Quality validity is exactly the full 3×3 accepted-input neighborhood. Preserve separate result/quality semantics and compare them with the existing whole-window GDAL oracle on small fixtures. Only projected metre horizontal grids with metre elevation are slope-eligible; return the plan's explicit eligibility reason for geographic/unknown units rather than assuming scale one. Results retain input generation, recipe/units and engine provenance. Definition/parameter editing is not introduced here. Refresh keeps the last successful result until the matching new input publishes; stale completions never replace it.

## 7. Display and previews without full-extent intermediates

### Native rendering contract

Serve a 256×256 PNG for `(entity kind, entity ID, generation ID, style, z, x, y)` or explicit empty/unavailable. Validate entity/generation ownership, integer tile coordinates and supported zoom before work. Reuse current `ColorRamp` stops/domain, clamp at end stops and interpolate colours consistently; valid zero/negative pixels are coloured, invalid pixels are transparent. For percent slope, convert to degrees with `atan(percent/100)` only for colour lookup in the existing degree ramp; retain percent numeric values and reported units. No raw file path, arbitrary CRS string, GDAL arguments or style expression comes from the WebView.

Use GDAL's existing coordinate-transform adapter to transform bounded batches of target pixel centres from EPSG:3857 into the generation lattice, preserving x/y axis order. Batch inputs and outputs within existing byte caps (at most 4096 points per invocation and also enforce byte limits); validate returned count and every coordinate. Failed transforms mean unavailable for that region, not a fabricated zero. Retain GDAL as projection authority; do not add a projection engine. Reuse `image` for native PNG encoding. Raster sampling and encoding stay off the UI thread.

For native-scale presentation, bilinearly sample the resolved lattice, normalizing over valid contributors; alpha is zero when there are none. For minification, select a power-of-two grid level from source-pixel footprint, use **valid-only mean** cells at that level, then interpolate. For each target sample, transform its centre and one-pixel x/y neighbours, take the larger Euclidean displacement in native cell coordinates, and choose `max(0, floor(log2(max(displacement, 1))))`; bound exponent/arithmetic before using it. The rule uses global target coordinates, not a tile-local origin, so a shared sample has the same level on either tile. Level cells are aligned to the fixed layer lattice, so results do not depend on member boundaries or import order once numeric coverage is resolved. A reduced cell is defined by its exact native rectangle: sum/count valid native cells only. Whole enclosed blocks can contribute stored f64 sum/count; partial blocks use bounded reads. Page the occupied index, never visit missing bounding-box blocks. Cache reduced cells/tiles within the shared budgets, not a mandatory whole-generation overview pyramid. Means are display derivatives only, never slope/numeric input. Include a one-pixel sampling border and test neighbouring tiles for coordinate/alpha seams. This changes display resampling implementation, not source samples or UI layout; pixel-identical PNGs from the old GDAL pyramid are not required.

This deliberately avoids a global VRT with an unbounded source list and avoids introducing a custom GDAL driver. First cold tiles may scan occupied data for reduction; latency is measured, not promised. Caching/grouping reads is delegated within the fixed numeric/display semantics. If representative navigation cannot remain usable, report measured bottlenecks; do not hide it with eager union materialization or a new engine.

Existing Before/After previews use the same renderer on a fixed-size target whose **two dimensions are each at most 512**, preserving aspect ratio and common Before/After colour scale. Do not retain `-ts 512 0` for arbitrarily tall extents. Sample windows refer to one immutable/staged candidate; preview failure never implicitly applies an import.

### Desktop transport, ownership and cache

Add a tagged tile-source descriptor to the existing library presentation contract: legacy asset template or native generation tile source. No fake filesystem path for a new generation. Add a Desktop-only `canopi-raster://` MapLibre custom protocol adapter, installed/disposed with the existing map surface lifecycle and HMR. Use generated executor-backed native tile commands returning bounded encoded bytes (maximum 1 MiB PNG response for a 256×256 tile) and an explicit empty/unavailable outcome. MapLibre's protocol returns the PNG ArrayBuffer; do not base64 an entire raster. Keep the legacy asset path adapter for preserved generations until their bounded adapter is ready. Web continues preserving Design references without importing Tauri or serving local rasters.

The library owns native request identity/cancellation and leases. Register requests before queuing so cancellation racing start cannot be lost; a disposed map/session fences every late response. The frontend uses the protocol AbortController, cancels obsolete queued requests and discards stale results even if native completion wins the race. If adding a synchronous cancel command, it only signals bounded in-memory state and must be registered in the native command policy like existing cancels. No filesystem/decoding on a synchronous command.

Allow at most two active display/numeric read requests and 32 queued display requests library-wide, with obsolete work cancelled before newer viewport work. Heavy work calls the resolver directly under its heavy lease rather than recursively taking a display request slot. Share a 128 MiB decoded/reduction/image cache budget and 512 MiB reproducible display-disk cache across source and result generations; cache identity includes immutable generation, style/version and tile/level. Use byte accounting, leases and eviction of unleased entries; never evict original/member/history blocks as cache. Under full leased budgets, decline/defer work explicitly rather than exceeding the bound. Cache writes use owned temp files and atomic publication; interrupted cache work is disposable, never a Ready dependency. Generation deletion/map disposal settles requests and closes descriptors.

## 8. Resource admission and conditional limit removal

Retain the accepted reader's 64 MiB per-operation buffer bound and combined capacity checks, extended to all simultaneously live job outputs. Use checked source/block counts and sum original-copy bytes still to be written, controlled COG, new member/resolved/result blocks, metadata, scratch export and 256 MiB reserve as applicable to each phase; do not double-charge already allocated files or count shared assets as new. Recheck before bounded writes and propagate failures. Disk observations are not reservations. Keep GDAL caches/warp memory/threads explicitly bounded per child through the engine adapter, and measure parent plus concurrently live children/read work, not just Rust Vec sizes.

Remove the old 16-file/512 MiB/1 GiB/25M-cell limits **only after all production callers are migrated and the gates below pass**. Arithmetic representability, supported format/CRS, available disk, cancellation and explicit byte/queue budgets remain. No replacement arbitrary pixel/count cap. Until verification, use test-only admission configuration to exercise large inputs without exposing unsupported large jobs in production. If a required large fixture/environment is unavailable, finish the implementation and all other tests, retain production admission limits and report that exact incomplete gate; do not call capacity enabled.

The target remains at most **1 GiB combined incremental working memory**, subtracting a recorded idle app baseline and including native raster children and concurrent reads. Use a sampled process-tree measurement with documented interval plus allocation/cache/queue counters; do not claim OS enforcement or exact peaks from sampling. No WASM is used in this slice, so WASM heap is not applicable. A sample over budget fails the gate. Cancellation stops new scheduling immediately and owned running work settles within five seconds in controlled tests, including a stalled child. No whole-grid mmap is a bounded-memory substitute.
