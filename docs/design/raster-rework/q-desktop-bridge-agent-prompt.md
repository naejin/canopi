## Isolated host and byte-read interface

Create `scripts/raster-qualification/desktop-host/` with its own Cargo workspace/lock, Tauri config and bundled frontend build. Do not add it to the production workspace or modify Desktop manifests, IPC registration, catalogue or application data. Reuse installed frontend TypeScript/Vite and `@tauri-apps/api`; use a separate TS configuration with DOM/worker libraries rather than broadening the Node evaluator configuration. Record locked host/runtime versions and reproducible build commands. Bundle local assets: no dev server in an evidentiary run. This is a qualification status surface, not a product UI prototype.

One host-run owner owns the worker, native handles, pending requests, timeout and teardown. At startup the native host receives an explicit manifest of fixture paths, expected hashes and immutable fixture-generation IDs from the TS launcher. Canonicalize, open read-only and verify bytes/hash before admitting a fixture; retain the opened file descriptor. Frontend code receives only opaque run-scoped handles and size/identity, never arbitrary read paths. Do not provide a command to open an arbitrary renderer-supplied path.

Operational seam: `read(handle, offset, length, requestId)` returns exactly that byte interval or a structured failure; `close(handle)` is idempotent; run teardown revokes every handle. Offsets and lengths must be whole, nonnegative and overflow-safe, length positive, within file size and at most 4 MiB. Reject a request for the entire artifact, unknown/closed/wrong-run handles, duplicate in-flight request IDs, overflow and out-of-range intervals before reading. Native work is executor-backed async; no filesystem work on the UI thread. Use two active reads and at most 32 waiting requests; reject excess work rather than growing an unbounded queue.

Worker messages carry handle/run/request identity and bounded byte requests. The main WebView relays native invocations and transfers returned buffers to the worker; it does not decode rasters. The worker uses `new CogStream(prefixBytes)`, `tiles_for_window` and `decode_tile_f64` on requested tiles, copying only intersecting cells into windows of at most 1024×1024. Start with a 64 KiB header prefix, grow only on an actual header-shortage response, never beyond 1 MiB or to the whole file. Reject unsupported layout/oversize tile instead of whole-file fallback. Guard disposal once. Bound outstanding requests and decoded retention by the existing 128 MiB cache limit; no cache is required for this pilot.

The native reader owns an independent ledger of actual reads: fixture identity, request ID, offset, requested/returned length, outcome, aggregate bytes, maximum read, active/queued high water. Compare it with worker counters, never reconstruct the native ledger from worker claims. Count header reads as well as tile reads. Hash/preflight reads are separately labelled reference/precondition I/O, not candidate range reads. Cancellation stops scheduling, drops stale replies and releases run-owned resources within the existing five-second target; on timeout terminate the worker, close handles and fail the pilot. This verifies pilot safety, not the full Q-CANCEL/Q-TEARDOWN capability suite.

## Small positive pilot and offline host evidence

Generate one 2048×2048 Float32 plane in a fresh owned run directory with TS streaming output: `z(column,row)=column-row`, zero-based cell indices, explicit nodata at `(100,100)` and `(1024,1024)` using sentinel `-9999`. Use EPSG:2154 and geotransform `[0,1,0,2048,0,-1]`. Use existing native GDAL commands to prepare an uncompressed tiled COG with 512-cell blocks and no overviews. Verify the prepared metadata and compute its actual hash; do not reuse private fixtures or relabel prepared data as an original. TS analytic expectations are independent of candidate decode. Generate a manifest for q2 and host before launching the host; observations record the files actually opened.

Read five level-zero windows `(x,y,w,h)`: `(0,0,128,128)`, `(480,480,128,128)`, `(1000,1000,128,128)`, `(1920,1920,128,128)`, `(0,1800,128,128)`. These cover boundaries, holes, valid zero/negative values and distant ranges. Check exact analytic integer values and validity for every cell. No slope/display benchmark or larger fixture is included. The candidate's individual reads must remain bounded and total bytes for this pilot must be below the full derivative size; record duplicate/header reads honestly. If the artifact layout prevents this, report a failed pilot, not invented byte savings.

Use the packaged/bundled local Tauri executable (not Vite dev) on the available OS. Worker JS and WASM must load from bundled local assets. Deny outbound network for the pilot using available sandbox/firewall tooling without changing machine-wide policy; also restrict host navigation/connect policy to local resources and record asset origins. If network denial or a graphical WebView cannot be exercised, Q-HOST-1 remains unmeasured. A Chromium run or a browser-branded WebKit run is not Desktop evidence. Record OS, WebView/runtime/build versions, worker-start handshake, WASM load outcome and the native host run nonce. Do not claim cross-platform packaging from one host.

Use a ten-minute pilot deadline and 256 MiB generated-fixture/run-output cap (excluding build artifacts); these are safety limits for this small experiment, not replacements for plan budgets. Do not download or build a different engine to make it pass. `candidates.json` already records that published Whitebox 0.5.1 does not match the source pin: preserve that correspondence failure. A positive exploratory transport observation can still be useful, but cannot qualify the pinned route by hiding this mismatch. Deliver a measured engine/packaging failure to the user rather than selecting a fallback.
