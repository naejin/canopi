R1-A — declaration correspondence
--------------------------------------------------------------------------

RED

  Before the mapping was rewritten, the disposition's four R1-A cases all passed
  through the real CLI while the three artifact-record assertions were satisfied by
  any matching name prefix, so the new tests failed for the intended reason:

  $ node --test dist/tests/r1aCorrespondence.test.js
  not ok 2  every required artifact needs its own integrity record
  not ok 3  every required artifact needs its own version record
  not ok 4  every required artifact needs its own license record
  # pass 3 # fail 6

GREEN

  Correspondence is now compared against the declaration at three independent
  points, and the required set comes from the declaration rather than the supplied
  names:

  - the record's version must be the version the route declares for that artifact;
  - the pin the record claims must be the pin the declaration names, so two
    report-owned strings agreeing is not mistaken for pin verification;
  - the built revision must equal that pin, and `matches: true` does not excuse a
    disagreement.

  A record naming an artifact outside the required set fails. A missing record for a
  required artifact is a gap. Duplicate verified-artifact identities fail before any
  comparison, so a wrong-version duplicate cannot be prepended and ignored. An absent
  pin declaration blocks correspondence rather than passing it.

  $ node --test dist/tests/r1aCorrespondence.test.js
  # tests 10 # pass 10 # fail 0

  `SourceView` now carries the declared expectations, so a mapping can consult an
  independent declaration without a second input path. This is the interface change
  the family needed: R1-A was not a missing comparison but a declaration that
  arrived and was then never read.

The transport declaration
--------------------------------------------------------------------------

The review's R1-C item about HTTP Range was a **wrong declaration**, not a missing
comparison. The plan says numeric windows are read "via the intended
Desktop/native/worker bridge", that "Q must qualify this local bridge, not just HTTP
COG access", and that a remote HTTP demo "does not qualify local access". The route
declaration nonetheless expected `http-range`, so the comparison ran and passed
against the capability the plan rules out.

  before:  control declares http-range, expectation is http-range -> assertion pass
  after:   expectation is the scoped local bridge
           control declares the local bridge        -> assertion pass
           source declares http-range               -> assertion fail, naming http-range

Two committed tests had been written around the wrong expectation and were
correcting the code toward the defect. Both were rewritten against the plan rather
than the reverse:
  - `C3: an observed transport that is not the required one cannot qualify` became
    `C3: an HTTP-only measurement cannot qualify the proposed local transport`;
  - the sweep's transport mutation now targets the transport assertion, not the
    window assertion.

R1-B — failure retained before gaps
--------------------------------------------------------------------------

Four independent mechanisms, each fixed where the finding was discarded:

  1. sampling: the reduction returned `inconclusive` at the first missing field, so a
     900 ms cadence violation on the same run was lost. It now collects violations and
     gaps separately and reduces once.
  2. memory: `raws` was filtered while indexes came from measurement order, so a
     leading null shifted every pairing and a 2048 MiB peak was read from the wrong
     record. The reader now keys off the record itself.
  3. sidecar: a missing observed hash returned `inconclusive` before the recorded
     non-survival was read. A present `after: false` (and a `before: false`) now fails
     first.
  4. fixture declaration: a declaration with one incomplete member was rejected whole,
     so its resolved members were never compared and a conflicting hash was lost. The
     validator now keeps the members it resolved.

  before -> after, through the CLI:
    B1  inconclusive -> fail  (sampling-meets-requirement=fail, reason names 900 ms)
    B2  inconclusive -> fail  (candidate-memory-within-budget=fail, reason names the budget)
    B3  inconclusive -> fail  (sidecar-unchanged=fail, "did not survive preparation")
    B4  inconclusive -> fail  (hash conflict retained)

R1-C — scientific sufficiency
--------------------------------------------------------------------------

  C1 render reconciliation: `tilesRendered + failedTiles` must equal `tileRequests`,
     and `pageErrors` must be empty. A run reporting one rendered tile of 999 requests
     now fails `runs-report-successful-rendering`.
  C2 negative durations: a latency cannot be negative, so negative samples fail
     `hundred-valid-latencies-per-run` instead of being treated as fast runs.
  C3 ledger corroboration: the report's validated-window count and its ledger must
     agree. A ledger recording zero bytes over zero requests no longer corroborates
     nine validated windows.
  C4 window dimensions: a window is a whole positive number of cells, so a 0.5-cell
     dimension fails rather than being compared as a size.
  C5 preparation sufficiency: the contract obligation is "tiled *and* bounded", and the
     producer reports those as `derived-tiled` and `derived-block-bounded`. The mapping
     read only the first, so an unbounded tiled derivative passed. Both are now
     required and the more severe decides.

  R1-C audited rather than only repaired: every requirement mapping was read against
  what its assertion claims, and the four above were the ones whose producer evidence
  was insufficient. The remaining mappings read the observations their assertions name;
  the ones with no producer (member overview precedence, fixture-class coverage,
  in-flight cancellation, concurrent in-flight work, teardown release, disk-write
  injection, Desktop WebView, display disk cache, staging/free-space) stay explicit
  gaps.

R1-D — admission and policy boundary
--------------------------------------------------------------------------

  D1 a precondition that records no `met` now blocks the requirement;
  D2 `preconditions: null` (and `failures: null`) are malformed rather than absent;
  D3 a negative-control scope must be an explicit `expected-rejection:` declaration, so
     an arbitrary report-chosen prefix cannot exempt a positive failure — while a
     genuine scoped rejection still passes;
  D4 the envelope's experiment label must agree with the identity block;
  D5 preservation requires both the before and the after observation, in every

  D6 numeric overflow is rejected after decoding as well as for bare nonstandard

**Two zero results, reported rather than smoothed over.**

H1: the pin comparison does not fail the suite alone. Any input it catches is also
caught by the built-revision comparison immediately after it — if the recorded pin is
not the declared pin, the built revision cannot equal it either. The pair is
load-bearing (H1b fails six tests) but each half is redundant. The guard is kept for
the clearer diagnostic it produces, and this is recorded as redundancy rather than
coverage.

H9: the envelope/identity check is redundant with identity verification, which
independently fails a report whose identity names a different experiment than the role
expects. H9 reports zero because removing it cannot change a verdict for the cases
tested.

**One probe reading was wrong before it was right.** The first H1 measurement appeared
to show the pin check never executing. That was a measurement artifact: the probe
instrumented `process.stderr`, which the Node test runner captures rather than
forwarding. The check was confirmed to execute by throwing from it (two tests then
failed), and the probe was re-measured with a compiling edit and a failing-test count
before any conclusion was drawn.

H9's first probe reported BUILD FAILED because the edit left an unused operand in a
position the compiler rejects. It was rewritten as a compiling guard removal.
