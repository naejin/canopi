Consolidated admission repair — captured cycle, sensitivity and self-review evidence
====================================================================================

Baseline 29789fe5 (atop 5becb043/9fea1931 and the prior accepted stack). Commands
run from the repository root. Outputs are trimmed to the decisive lines. Each RED
was captured before the corresponding change; each sensitivity probe was captured
by reverting one guard in a working tree and restoring it afterwards. Nothing here
is reconstructed after the fact.

Test-count progression: 209 (baseline) -> 213 (C6 verdict types) -> 219 (C6
admission required) -> 222 (C6 failure outranks gap) -> 227 (C2 loader totality)
-> 232 (C3 role identity) -> 238 (C1 strict leaves) -> 242 (C4 assertion
evidence) -> 250 (C5 budgets) -> 256 (C8 cross-layer) -> 258 (C7 output failure)
-> 260 (C8 observed-failure severity).

Every cycle was driven from a coherent passing control through the raw report, the
real assembler and the real gate. Expected values were written down from the
acceptance contract and the plan's budgets before the code under test ran; no
oracle in these cycles is computed by the module being tested.

C8 cross-layer invariants
--------------------------------------------------------------------------

  Four fault kinds (source assertion failure, source result failure, window over
  the contract limit, resource budget exceeded) crossed with four independent gap
  kinds (identity removed, runId removed, fixture manifest removed, fixture
  coverage lost) at the source and declaration layers, plus order permutation,
  plus add-unrelated-evidence and remove-required-evidence invariants.

  RED found one real contract violation: a window over the contract limit plus a
  removed runId reduced to `inconclusive`, because the derived assertion failure
  raised only the reason list and not the record's severity. The reduction was
  fixed so a measured violation outranks a gap in the source it was measured from.

  A second asymmetry was found and fixed while reconciling the real evidence: an
  entry whose source was not admitted filed its already-recorded failures into
  `observed` without reducing them, so a recorded failure could grade down to a
  gap. The gate now keeps an observed failure's severity.

the requirement verdicts read back through the real `gate` command. Cases

     transport, bumped artifact version, wrong fixture hash)  no pass
  E. over-limit and missing measurements (decoded cache over budget,
     counter removed, windows removed, window over limit) .... no pass
  F. failure plus gap combinations (failure + missing runId,

  G. declarations (duplicate manifest key, string member, no manifest)
