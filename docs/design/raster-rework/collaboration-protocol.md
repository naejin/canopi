## Evidence and task-local improvement

Claims name their actual boundary: numeric helper, production caller, settled job, saved library, live pixels, browser or packaged platform. Helper tests and catalogue rows cannot substitute for the mounted map. Inputs and expected outputs must independently support the claimed behavior. Red-before-green is recorded only when observed, with the failing reason and healthy control; a final passing test does not establish it retrospectively.

Maintain one completion receipt and bd checkpoints. Record only material events that affect correctness, repeatability or delivery effort: missing decisions, repeated command failures, misleading fixtures, tool false successes, escaped invariants and avoidable requests for continuation. Consolidate duplicate events; do not create a diary or second task tracker. Sensitive files, credentials and private rasters stay out of committed evidence.

A demonstrated task-local tooling problem may be repaired during this assignment if the change is small, reversible, uses existing dependencies and directly improves implementation or trustworthy verification. Prefer a regression, correction to an existing script, or replacement of a stale guide. Verify the failing case and healthy control, then return to product work. Compare experiment restoration with saved starting bytes, not HEAD when the starting file was dirty. Do not hide a failed command behind a successful wrapper.

Record whether a fix helped on its next actual use; otherwise the benefit is untested. Before adding a rule, check whether an existing rule already covered the failure. Broader skills, shared workflow automation, dependency changes or unrelated tool projects get a scoped proposal/follow-up and falsifiable next-use test; this assignment does not authorize installing them. Continuous improvement must reduce demonstrated friction without becoming another qualification project.

## Debrief and adoption

The existing debrief owns one final synthesis. For each material intervention record **failure/revision → classification/owner → smallest change → evidence/next use → keep/revise/drop → owner/follow-up**. Distinguish design omission, implementation deviation, test/oracle gap, reviewer oversight and environment/tool limitation; allow overlap. The main agent owns overprescription and missed review boundaries as well as omitted decisions.

Compare useful capability delivered, necessary versus removed machinery, defects found before versus after handoff, and necessary decision exchanges versus avoidable continuation. Time/cost are unknown unless directly observed with scope; test totals, line counts and assumed model prices do not prove savings. The user's implementation-agent preference is an execution preference, not measured evidence of cost reduction.

At final handoff name improvements already applied, evidence for keeping them, and proposals still awaiting a real test. Promote demonstrated lessons to the narrowest maintained test/script/guide, remove superseded instructions, and link rather than copy authorities. Independent review adds its escapes and disposition to the same record. A partial delivery produces a partial debrief; neither is relabelled complete to avoid a material blocker.
