# Standard COG assets with sparse numeric generations

Status: proposed — revised direction for the user-forwarded bounded-generation assignment; not implemented. Replaces this ADR's unimplemented raw-block choice at `24fd1a56`.
Current guidance: [bounded-generation design](../design/raster-rework/bounded-generation-design.md), [LiDAR guide](../agent/lidar.md).

Canopi's immutable ordered member occurrences remain the authority for source composition and targeted undo. Retain each interpretation's prepared standard COG. New generations materialize resolved **occupied** 1024×1024 spatial chunks as standard COGs, indexed in the existing catalogue and shared by immutable asset identity. TIFF tiles inside those files remain 256×256. Legacy generations remain readable through bounded adapters; no authoritative full-union mosaic or union-sized sparse file is created.

Reuse GDAL's existing controlled COG creation and GeoLibre's selected native decoder, `wbgeotiff`. Source-specific effective NoData remains interpretation metadata; resolved/result files use NaN NoData because accepted valid samples are finite. Separate analysis quality, when needed, uses 0/1 Float32 COGs in the same supported profile. This avoids assuming internal-mask support or introducing another decoder profile. Raw/ENVI files are bounded disposable conversion scratch, not a new persistent format. The design owns exact profile and ownership rules.

This trades retained source plus resolved-chunk bytes and a sparse catalogue for bounded work across distant extents and reuse of unchanged chunks. COG does not implement history/undo or guarantee bounded application work by itself. A single COG/VRT spanning all coverage was rejected because it does not by itself bound empty-extent work, updates or downstream display/slope. Member history alone was rejected as the only read representation because read cost would grow with prior occurrences. The remaining catalogue/index is Canopi-specific application metadata, not a claim to eliminate all custom persistence.

The earlier raw/mask proposal confused the necessary bounded-access contract with an optional encoding choice. No implementation failure demonstrated that standard TIFF was insufficient. The main agent withdrew that proposal before implementation after the user's reuse challenge; the historical text remains in `24fd1a56`. Reusing a standard format is expected to reduce encoding maintenance, not yet measured to reduce total delivery cost. The first B1 round-trip validates interoperability and committed-file lifetime before caller migration, without restarting tool qualification.

Numeric publication is independent of reproducible display caches. Existing review/Apply and map UI stay usable through the new resolver and a generation-scoped tile transport. The implementation specification fixes migration, ownership, resource admission, and the evidence required before capacity limits can be removed; this ADR does not authorize a release or promise unmeasured capacity.
