## 3. Common procedures

### 3.1 Live check on an isolated review instance

The procedure (when, the detached worktree with its catalog copy, the profile, ports, launch, driving, screenshots, frame-time limits) is the guide's "Live check" ([`agentic-delivery.md`](../guides/agentic-delivery.md)). The orchard master (format v9, 2,200 plants, 24 zones, 106 notes) is never opened in the app; `.tmp/dense-canvas-review/orchard.canopi` is not it (v5, refused).

Reference screenshots for "unchanged" checks are taken with the same profile, Design, window size and camera on the commit before the step, with the basemap hidden first (Layers › Map › Background › None, Plain paper; `basemap_visible` is a device setting in the profile's user DB, so it stays off for every later comparison), because OpenFreeMap tiles load over the network and change on their own. Autosave writes into the profile's copy of the orchard, so copy it again before each comparison.

### 3.2 Web Edition checks (Chromium and WebKit)

The trigger and the local Docker run are the guide's "Web check"; in phase 0 it alone caught a crash of the real renderer (Pixi filters never registered) that unit tests with a recording renderer could not see.

The CI job `.github/workflows/web-edition-browsers.yml` (canopi-9x95) serves the built Web Edition (`npx vite preview --mode web --port 4174 --strictPort`, base URL `http://localhost:4174/app/web.html`) and runs `npx playwright test e2e/canvas --project=chromium --project=webkit` in the image `mcr.microsoft.com/playwright:v1.63.0-noble`, whose tag matches the exact `@playwright/test` pin in `desktop/web/package.json`. Its scenarios are `desktop/web/e2e/canvas/base.spec.ts` (open the base fixture, pan, zoom, Present, PDF) and `phase-0-refactor.spec.ts` (phase 0's live-check steps 2–6 and a viewport resize), on the committed fixture `desktop/web/e2e/fixtures/canvas-base.canopi`; the release close adds `v2.spec.ts` (U1) and moves into it what still holds of `phase-0-refactor.spec.ts`, which it deletes. Until then a step that changes what a scenario asserts or shows has the main agent rewrite the assertion or re-record the baseline in the merge that changes it.

- **Network.** Every spec imports `test` from `desktop/web/e2e/support/offline.ts`, which aborts every request whose origin is not the preview server, so the default OpenFreeMap basemap never installs and baselines do not follow the tiles; a spec that fails on console errors allows exactly "Map basemap style failed to load:".
- **Baselines.** `toHaveScreenshot` baselines are recorded only in that image, never with the host's browsers: the guide's Docker command with `--update-snapshots`, after `npm run build:web` and `df -h /`; if Docker fails, the job's `workflow_dispatch` input `update_snapshots` uploads them as an artifact. Screenshots are taken on settled states only.
- **Fixture.** `canvas-base.canopi` carries the build's `CURRENT_CANOPI_FILE_VERSION`; a format change re-saves it in the same commit. The orchard never enters CI; orchard-scale evidence is recorded by hand.
- **Version.** A Playwright bump is its own commit, with the image tag and the re-recorded baselines.
- **By hand.** Chromium may run on the host (`npx playwright install chromium`, then `npx playwright test e2e/canvas --project=chromium`); WebKit runs locally only in the image, never with `sudo` (this host lacks `libavif16`).
- **Limits**, recorded in each bead: multi-touch is Chromium-only (CDP `Input.dispatchTouchEvent`); WebKit trackpad `gesture*` events cannot be produced natively and are covered by fixtures E9 and E10. Playwright's `page.mouse` sends real right and middle buttons, so the job is the standing evidence for the right-click order in Chromium (for WebView2) and WebKit (for WKWebView).

### 3.3 Inventory

Inventory rows have stable IDs by group: `INV-CAM` (camera and view transform), `INV-XF` (copies of the world-to-screen transform), `INV-TOOL` (tools, hit testing, snapping), `INV-REN` (rendering and per-frame work), `INV-ENT` (entanglement), `INV-LSN` (raw listeners), `INV-WR` (camera writers), `INV-KEY` and `INV-FOC` (keyboard and focus), `INV-DATA` (stored data), `INV-DOC` (docs, patterns, boards, locales) and `INV-TEST`. Each row's phase column names the work left, in this plan's phase names; `plan` rows are the documents the release close checks. A row is cleared when its fate (keep, change, delete) is done by the last phase its column names. The phase bead lists the row IDs it cleared, and a phase does not close with one of its rows open unless the inventory re-homes it to a later phase. Cleared rows are deleted from the inventory at each phase close.

**Conventions still in force** (code comments cite them):

- **Draft strokes.** A draft converts a screen length to world units at the scale it draws with, and re-traces when that scale changes.

## 5. Policy tests

Every new policy rule's `name` (the AST policy's `name`, the regex policy's `it` title in `canvas-boundaries.test.ts`) starts with its P-id and a space, then says what that rule checks, for example `'P5 tools import no MapLibre, DOM or Pixi'`; a row with several rules (P5's `forbid-imports` and `confine-symbols`) gives each its own unique name under the same P-id. The table's Name column titles the row, not the string. Existing policies keep their names. AST policies go in `__tests__/frontend-architecture-policies.test.ts` with the existing kinds (`__tests__/support/architecture/policy-harness.ts`); each gets a planted-graph negative test in the pattern of that file. `forbid-source-symbols` has no `exceptFrom`, so a symbol rule with exempt files is written as `confine-symbols` (`from` the area, `allowedFrom` the exempt files plus tests). `forbid-source-symbols` and `confine-symbols` match every identifier (`__tests__/support/architecture/source-facts.ts:108`), so confined names must be distinctive. `forbid-calls` compares `targets` globs with the full callee text (`attachment.map.jumpTo`), and records `property` only for member calls, so a bare call (`selectCanvasTool('polygon')`) is caught by `confine-symbols`, not by `properties`. Regex policies go in `__tests__/canvas-boundaries.test.ts`, which walks every `.ts`/`.tsx` file under `src/` (as `frontend-architecture-policies.test.ts:2121` does with `readdirSync`), skips tests, applies each regex to every file and compares the hits against the policy's named allowlist; each regex has one planted-file negative test, so a coupling reintroduced in a new file fails. Before an allowlist is written, its bead records the inventory counts, so every allowlist entry is named, with its count and the phase that removes it.
